# 测试数据库安全规范

## 核心原则

测试只使用本次运行独占、可丢弃的本地 `file:` SQLite/libSQL 数据库。不得对开发、预发布或生产数据库执行测试迁移、seed、清空或写入。

## 执行契约

1. 先判断测试是否真的需要数据库；纯业务规则优先使用现有 fake repository 或无数据库测试。不要仅为“更完整”而另建数据库。
2. 创建数据库前，在 commentary 中告知用户用途；预计生成大型隔离副本或测试数据时同时说明规模。无需把正常的临时测试库包装成项目基础设施。
3. 使用 `mktemp -d` 创建本次运行独占目录，例如 `/private/tmp/honeycomb-test.<uid>.XXXXXXXX/`。取得目录后下一步立即安装最小清理 trap，再执行任何可能失败的检查或命令。确认目录归当前用户所有、不是符号链接；数据库、WAL/SHM、服务日志和 Playwright 结果都放入其中。禁止使用固定文件名或复用旧目录。
4. 如需加载 `.env`，必须在加载后显式覆盖数据库变量。迁移、seed、应用服务和测试启动前，规范化并断言数据库父目录就是本次临时目录，且 URL 为 `file:`；遇到 `libsql:`、`http:`、`https:`、空值、`..` 逃逸或仓库内路径立即停止，禁止回退到默认远程地址。本地 `TURSO_TOKEN` 使用非空测试哨兵值，不继承真实凭据。
5. Seed 必须通过项目现有 `scripts/e2e-seed-policy.ts` 门禁，并显式设置 `E2E_SEED=1`。数据库耦合的 E2E 使用本次环境启动专属服务；端口已有监听时失败，不连接或终止未知服务。
6. 清理 trap 覆盖 `EXIT HUP INT TERM`：记录并只停止本次启动且已验证的子进程或进程组，有限等待并确认进程消失，必要时只强制终止该已验证目标；随后删除整个临时目录并保留原退出码。测试成功、失败或常规中断都执行清理。
7. 完成后验证已记录进程均已退出且临时目录确已删除，再向用户报告测试阶段、退出结果和清理结果。任一验证失败时必须给出精确 PID 和/或残留路径，不得声称“无残留”。`SIGKILL`、掉电等无法触发 trap 的情况，只报告旧目录；未获得用户明确清理授权前不自动删除。

## 边界

- 不删除名称或所有权不明确的旧数据库、baseline、stage 或恢复备份；需要扩大清理范围时先取得用户明确授权。
- 只有用户明确要求保留可复现实验数据时，才允许跳过自动删除，并必须说明保存位置和删除方式。
- 迁移 SQL、schema 和测试夹具属于代码资产，不因本规范被当作临时数据库删除。

## 完成检查

- 数据库 URL 是本次随机目录下的 `file:` 路径。
- 未读取或写入远程数据库。
- 测试服务与数据库使用同一组显式环境变量。
- 临时数据库、sidecar、日志和测试结果已清理或已准确披露残留。
