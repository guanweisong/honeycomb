# 测试缺口审查与补强

## 基线与口径

本轮基于 PR #22 的 `0cee07e2b50dd3b969c5eda00dd262b784f6c204`，tree 为 `c6720196cfea9610e1364686e82ab5d0cad16ff1`。基线 CI 的 3163 项普通测试、103 项进程测试及 67 项 E2E 通过只证明当时测试结果，不证明行为没有遗漏，也不是本轮新增测试的执行结果。

完整受版本管理库存为 1791 个文件。生产源码、工具与配置按用途和现有测试证据登记；文档、历史规格、资源和生成元数据单独分类。不要求每个文件都有同名测试，也不把 import 图、覆盖率或目录扫描称为逐分支证明。类型声明以编译契约验证，薄路由由页面、集成与浏览器旅程提供证据。

## 本轮补强

| 风险                       | 原有证据为何不足                                                   | 新增证据                                                                                                                   |
| -------------------------- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 登录历史用户隔离、保留边界 | 原 mock 忽略 where/orderBy，错误用户参数也会返回相同行             | 真实 Drizzle SQL 编译结果检查用户参数、倒序、投影和精确 90 天 `<` 条件；插入失败不执行清理                                 |
| 已有设置升级丢失翻译       | 现有 snapshot 测试先迁移空库再造数据                               | 真实 migrator 升级已有中英文设置，验证父字段、外键、revision 和备份表清理；注入恢复失败验证完整回滚                        |
| 备份成功及失败关闭         | 原测试只有符号链接拒绝                                             | mock 外部 client，真实独占临时文件验证哈希、私有权限、脱敏；sync/integrity/inventory 失败不发布成功 metadata 且关闭 client |
| 滚动 hook 边界与清理       | 上层组件 mock 了 hook                                              | 真实 React hook 验证初始值、严格阈值、阈值变化和监听清理                                                                   |
| 并发请求上下文串线         | 原测试只有单个 async scope                                         | 两个 Promise 屏障交错恢复，验证各自 requestId 和作用域退出无泄漏                                                           |
| manifest/robots 返回行为   | 浏览器仅检查 manifest 链接和 MIME                                  | 直接路由返回值验证语言、fallback、start URL、设置失败、robots 私有路径和 sitemap origin                                    |
| 真实 Next 404              | 组件 render 与 mock notFound 不能证明路由匹配及多 root layout 行为 | 6 项浏览器路径覆盖未知路由、缺失内容及非法 ID，检查状态、noindex、真实 fallback 和返回首页                                 |
| 真实表单登录               | 已有跳转测试 mock 认证和目标页；render fixture 直接 API 登录       | 1 项表单→真实认证请求→HttpOnly cookie→受保护页面→刷新旅程，仅第三方验证码 widget 使用测试 fixture                          |

新测试不改变生产行为、覆盖率分母/阈值、测试 timeout 或已有断言。真实数据库只使用独占可丢弃本地 SQLite；备份 client 始终 mock，不连接远程数据库。

## 尚未宣称覆盖的范围

- PWA 的真实版本更新接管和旧缓存清理，不能由已有首次安装/离线导航替代。
- E2E preflight 子进程信号与退出码传播、部分构建脚本故障分支仍有进一步补测空间。
- Mock 的管理 CRUD 浏览器契约不是所有业务的真实数据库 E2E。
- 每个文件的职责与已有证据登记不代表所有组合、每条分支或所有视觉表现已穷尽。
- 本地指定 Playwright 浏览器此前下载截断，本轮不重复无效下载；新增 E2E 的库存或类型检查不代表浏览器执行通过。需要发布授权后由当前精确 head 的 CI 补齐真实执行。

## 验证记录

定向验证与隔离最小变异已证明登录用户参数、迁移翻译恢复、备份 integrity guard 和滚动严格边界的回归会使新测试失败。最终冻结树的完整命令结果在交付记录中单独列出；不得沿用基线 CI 或定向通过冒充全量通过。
