# 公开缓存与离线验收

本文件记录当前实现的缓存链路及证据边界，不改变缓存/PWA 合同，不承诺即时撤回。更新日期：2026-10-20。

## 实际链路

| 层                | 内容与配置                                                                                          | 失效/恢复路径                                                      | 尚不能据此保证的事                                                                 |
| ----------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| React 请求缓存    | `public-queries.ts` 的 `cache()` 去重公开查询；评论仅请求内缓存                                     | 新请求重新读取；评论在 `connection()` 后查询                       | 不负责清除浏览器/CDN 副本                                                          |
| Next 远程数据缓存 | 公开布局、文章/页面详情、文章索引等使用 `use cache: remote`、`cacheLife("max")` 和结构化标签        | 提交后 `publicContentInvalidator` 失效布局/索引/详情标签与语言路由 | 生产远程处理器及 CDN 行为未实测，不能把标签调用成功等同全球副本即时清除            |
| Upstash 文章索引  | `post-list-cache.ts` 以缓存版本与查询输入组成键，结果保存 3600 秒；缺失/不可用时读数据库               | 写入后提升索引缓存版本；旧格式不通过运行时 schema 时按未命中处理   | 缓存服务故障、版本提升失败和外层缓存叠加时，不能仅以 3600 秒宣称端到端最大陈旧时间 |
| sitemap           | `sitemap-data.ts` 缓存 300 秒，并使用 sitemap 标签                                                  | 内容变更提交后按计划失效 sitemap 标签                              | CDN 或第三方搜索引擎已有副本不受该时间保证                                         |
| Router Cache      | `next.config.ts` 的动态路由 `staleTimes.dynamic = 300`                                              | 页面刷新、导航及认证退出硬导航；后台列表另有查询刷新               | 已打开页面不自动变成最新内容；不能追回已经读取的数据                               |
| HTTP/CDN          | 响应由 Next、部署平台及资源存储共同产生；工程统一安全响应头不构成完整 CDN 缓存配置                  | 由框架/平台失效及资源键管理                                        | 当前未获取生产响应头和 CDN 配置，TTL、区域传播与失效失败窗口均未验证               |
| Service Worker    | 公开 HTML/RSC/数据优先网络，离线回退缓存；同源 `/api`、`/admin` 不进入公开运行时缓存规则            | 新网络响应更新缓存；失败使用缓存或静态离线页                       | 公开历史副本可能离线可见；不新增撤回离线副本保证                                   |
| 图片及静态资源    | SW 图片 stale-while-revalidate；Next 图片优化 `minimumCacheTTL = 31536000`；对象 URL 独立于内容状态 | 新内容使用新对象键；缓存自身更新/淘汰                              | 文章撤回或数据库媒体状态变化不会让已公开的对象 URL 变私密                          |

Next 16.4.0 安装包的默认 `max` 配置为 stale 300 秒、revalidate 30 天、expire 365 天。这是版本对应的配置值，不是本项目生产环境的实测陈旧上限；升级框架需重新核对。

SW 的页面/RSC/数据缓存配置为最多 32 项、24 小时，使用 `maxAgeFrom: "last-used"`，不能解释为对象创建后必在 24 小时内消失。静态图片最多 64 项、30 天；跨源回退为 NetworkFirst、10 秒网络超时、1 小时淘汰配置。响应缓存插件拒绝 `private`、`no-store` 及非成功/非 opaque 响应，也拒绝继续使用带上述禁止指令的旧缓存条目。此检查不负责证明任意第三方 opaque 响应不存在敏感内容。

## 写入成功与公开刷新分开

`next-public-content-invalidator.ts` 只在业务提交后执行缓存失效，最多尝试两次缓存操作，不重新执行业务写入。失效降级返回 `degraded`，管理界面应显示内容已保存、公开刷新待确认，并使用既有受权限保护的刷新入口重试。

旧客户端缺失编辑版本时不得由服务端自动填充当前版本。旧缓存缺少新增字段时应按读模型校验失败处理；不能为兼容缓存而伪造版本 0。Service Worker、浏览器和第三方中的历史公开内容不能靠数据库迁移撤回。
