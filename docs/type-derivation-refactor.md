## 事实源和保留边界

- 列表过滤复用所属查询 schema，但服务端分页、排序默认不与 API 默认强行统一。schema optional 字段通过局部映射保留旧 `undefined` 语义，不增加通用泛型。
- 评论通知、公开评论节点、菜单树/选项、当前用户与保存反馈仅复用同语义字段，公开评论实际脱敏、页面版本及创建令牌隔离不变。
- 媒体注册/删除 callback 表达原始调用输入，使用已有 schema 的 `z.input`；当前这些 schema 输入输出相同，不以习惯性的 `z.output` 替代语义判断。上传准备结果和原始媒体 cover 继续独立。
- 编辑器已确认发布状态、认证 provider 和缓存 publicSync 收窄为实际权威集合；有效枚举字符串继续接受。UNKNOWN 防御用例不删除，通过明确编译负例保留运行时测试。
- Better Auth 泛型 `listAccounts` 不直接套未实例化的 ReturnType，避免字段退化为 any；实例化实际无 fetchOptions 调用后再取 id/providerId/accountId，保持三字段均为 string。
- OAuth 配置来自已有 env schema，安全环境、tRPC options、UI size/side 和本地化字段复用既有契约。观测与依赖审计目录仅合并相同成员，白名单值和顺序不变。
- CategoryNode 只有声明及历史迁移说明、无源码消费者，删除该死类型出口；历史迁移记录保留当时事实。UserListInput.email 继续显式内部扩展，不新增公开 API 字段。

## Link 的精确持久化类型例外

LinkRecord 固定选择 link 表的 7 个普通字段，status 单独保持 `EnableStatus | null`。只允许 `src/features/link/types/link.record.ts` 到 `src/lib/db/schema/link` 的 type-only 边；DB barrel、其他 DTO、运行时导入和 types→server 继续被拒绝。该表依赖中立 EnableStatus，而非 feature 派生 DTO，不形成反向类型环。

mapper 对原有 8 个字段显式赋值，不使用对象扩展隐式透传数据库新增列。创建、更新及列表的新列模拟用例先失败再通过；未知持久化状态仍在失效缓存前抛错。编译期固定字段白名单和运行时裁剪分别验证，不能互相替代。
