# 普通媒体注册与上线核对

## 上传合同

浏览器仍直接上传 R2，单文件最多 20 MiB、每批最多 20 个，支持 JPEG、PNG、GIF、WebP、AVIF，不代理上传请求体，也不提供跨请求配额。

`prepareUpload` 接收文件名、类型、大小和 SHA-256 摘要，复查当前上传权限，签发绑定账户、随机媒体 ID、临时 key、声明及有效期的 HMAC 意图和仅针对临时 key 的 PUT URL。准备阶段不创建数据库行。签名使用现有 AUTH_SECRET；更换该密钥会使未完成意图失效。

`registerUpload` 验签、检查账户和有效期、复查当前上传权限。已存在相同 ID 的普通记录直接返回，不重写、不宣称历史内容重新验证。不存在时先获取验证名额，再受限读取临时字节，核对大小及摘要并完整解码验证。每次注册尝试生成新最终 key，服务器将同一份已验证内存字节单次 PUT，只有确认成功才在短写事务中再次检查权限并按 ID 幂等插入普通记录。浏览器不能写入、删除最终 key；不再使用 COPY。

需要支持 Sharp/libvips 的 Node.js，不可迁往 Edge。保留 40M 总像素、100 帧及进程内两个读取/解码名额，所有退出路径释放；满额返回错误供手动重试，不排队。GET 加最终 PUT 增加最多 20 MiB 出站传输。真实峰值内存、托管时限和原生格式支持仍需验证。

R2 适配器的每次 HEAD、GET、PUT 或批量 DELETE 共用一个 30 秒截止时间，覆盖该次 SDK 重试、响应头及完整响应体消费；GET 中止会销毁流并释放注册验证名额。最终已验证字节 PUT 与批量 DELETE 的 SDK `maxAttempts` 仍为 1。它不是整个注册/删除事务的总时限，也不是供应商 SLA；超时仍可能伴随迟到写入，不能推断对象一定未改变。

应用不能防止持有桶级权限的其他程序改写文件，也不是对象锁或 WORM。公开桶、CDN 缓存和已下载数据不随数据库删除立即撤回。

## 失败、重试及人工核对

媒体只有普通记录，无上传/删除状态、恢复列、操作表或墓碑。管理页没有状态筛选、徽章、status/reconcile 接口；仅有当前请求的加载、错误和批次反馈。

- PUT 失败或响应未知：不注册，不通过 HEAD 将未知写入恢复为成功，不自动重试。手工重试使用新最终 key；迟到的旧写入可能成为孤立对象。
- 数据库提交响应未知：可能已提交，不删除候选。再次提交同一有效意图时，当前授权通过后可返回已存在记录。
- 并发注册：主键仅保留一行，但竞争失败的候选可能成为孤立对象，不自动清理。
- 同一记录已删除后，有效意图仍可在当前上传权限及字节验证通过后重新注册，使用新最终 key。没有消耗账本，因此不是永久一次性令牌。
- 过期意图需要重新准备上传；孤立临时对象或候选需要人工核对。没有自动恢复、自动重试或自动孤立对象清理。人工清理必须确认对象未被引用及在途写入风险，不能仅凭一次 HEAD 或宽限期推断绝对安全。

## 删除合同与覆盖范围

`destroy` 必须提交 `acknowledgeUnknownReferences: true`。服务在串行数据库写事务内复查删除权限、读取整批记录、检查整批已知引用，持有写事务一次批量删除去重对象键，再以每组最多 8 个并行 HEAD 核对缺失，最后物理删行并提交。不逐项执行删除前 HEAD；对象已缺失时幂等删除。任一已知引用阻塞则不删除任何对象或记录，不能自动置空封面绕过保护。

文章/页面保存在自己的写事务中验证封面及受管正文图片记录存在。正文解析包括各语言 img src、受管域名/path、query/fragment 和协议相对 URL；未改变的未知历史受管 URL 可以保留，新未知受管 URL 不允许加入。删除还检查链接 logo、用户图片和同 key/URL 别名。链接/用户写入未实施相同的媒体存在性检查；这不是全量引用完整性，未知历史内容、自定义位置、外部链接和不受控写入可能漏检。

用户已接受以下简化取舍：部分对象删除成功、对象操作超时晚到、数据库回滚或提交响应丢失都不能跨存储回滚，可能留下指向缺失文件的普通记录。错误提示要求人工核对，不能宣称整批没改动、会自动恢复或记录一定存在。失败时 UI 不乐观移除行/选择，刷新实际结果。持有数据库写锁进行网络 I/O 增加锁等待和超时风险。

数据库提交确认后，缓存刷新失败仍返回删除成功和 `publicSync: degraded`，不能把已提交删除当作失败重做。

## 0008 迁移及发布门禁

0007 是既有历史迁移，不得改写。0008 移除生命周期列/约束/索引，保留普通字段、ID、key/URL、时间及尺寸约束。新代码不兼容仍有状态的旧写入协议，不可仅隐藏旧状态或在旧表上开始普通写入。

1. 核对目标实际账本和 schema，不把历史文档当作当前生产状态证据。先只读统计 UPLOADING、DELETING、DELETED；任何未解决行均阻止迁移。不得静默提升为普通记录或丢弃，处理/导出/归档需单独审查及授权。
2. 验证可恢复备份，在独占隔离数据库演练完整待执行链；0008 在 foreign_keys=ON 下保存并恢复 post.cover_id，验证全部普通字段、封面、文章版本和 updatedAt 不变，验证中途失败回滚。不得依赖事务内 PRAGMA foreign_keys=OFF。
3. 另行取得生产迁移明确批准，安排停写并协调客户端/服务端切换。此次代码变更本身不授权生产迁移、对象删除、合并或部署。
4. 旧版曾向最终 key 签发一小时 PUT/DELETE；迁移不会撤销能力。若仍在历史凭证有效窗口，等待有效期及钟差余量，不能宣称旧凭证不会复活文件。
5. 回滚需停写、审核兼容补丁或恢复备份；不能直接启动旧可写服务，也不能用数据库备份恢复已删除对象。

## 真实运行环境验证

- 检查服务端 PutObject、GetObject、HeadObject、DeleteObjects 权限；临时 PUT 签名绑定类型/大小，浏览器自行设置 Content-Length，CORS 允许精确站点 origin 的 PUT，不需要浏览器 DELETE。
- 验证最终 PUT 自动重试关闭（maxAttempts=1），无最终 key 客户端写能力。测试桶验证临时覆盖、PUT 响应丢失/迟到、数据库提交响应丢失、部分删除及锁超时，不能使用生产对象做破坏性测试。
- 验证五种格式、20 MiB、全帧、截断/超限拒绝、双槽峰值资源、函数超时和真实托管 libSQL 写事务寿命。未验证前不扩大限制。
- 日志只记录安全分类和请求标识，不记录签名 URL、意图令牌、凭据、文件内容或原始异常敏感参数。

代码和本地测试不等于生产验证；真实 R2、CORS、资源、事务时限和公开缓存仍是发布门禁。

## 未迁移数据库的部署保护

新代码可能在自动预览中连接仍使用旧表结构的数据库。每次媒体列表、上传准备、注册或删除均以实际表列与 Drizzle 普通媒体模型的完整匹配为前提；文章/页面受控引用写入也在原事务内执行同一检查。旧结构、缺失或多余列、检查失败均返回服务暂不可用，在签发上传能力和存储操作之前停止，不读取媒体状态值、不自动执行迁移。检查不缓存，另行授权迁移完成后下次请求可恢复。该技术兼容保护不能代替停写、备份、迁移批准或真实运行环境验证。
