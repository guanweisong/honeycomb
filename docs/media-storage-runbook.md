# 媒体生命周期与上线核对

## 合同和限制

新上传仍由浏览器直传 R2，单文件最多 20 MiB，每批最多 20 个；支持 JPEG、PNG、GIF、WebP、AVIF。应用不把上传请求体代理到托管函数。

服务器先保存 UPLOADING 行，再签发仅限随机 temporary key 的一小时 PUT。最终 media key 只由服务器生成，每个上传行最多复制一次；COPY 客户端 maxAttempts=1。服务器通过 S3 API 读取该候选，检查实际字节数、声明类型与解码格式、完整图片内容和尺寸，然后条件绑定为 READY。READY 再确认只返回既有记录。客户端不再收到 DELETE URL，也不能提交任意 key 直接登记媒体。

完整解码有 40M 总像素和 100 帧上限。每个进程最多接纳两个候选读取/解码，先取得名额再 GET，所有退出路径释放；满额返回待确认，不排队、不把忙碌标成无效图片。这不是跨进程调度器，也不代替目标运行时的内存、时长和原生解码器验证。

不可变性是应用能力边界：临时 PUT 无权修改最终 key，应用永不再次写候选。不是 R2 对象锁或 WORM；拥有账户级写权限的其他程序仍可能修改对象。公开桶中的对象、CDN 缓存及已经下载的数据不能因为文章撤回或数据库删除而立即撤回。

## 四态与人工核对

- UPLOADING：没有可供选择的已验证媒体。候选尚未出现或存储/数据库结果不确定时保留原行、临时 key、最终 key 和尝试信息。
- READY：可以选择；新上传 verifiedAt 非空。历史迁移行 verifiedAt 为空，只表示沿用既有可用性，不表示已验证历史字节。
- DELETING：已阻止受控保存路径新增引用。继续核对同一个原始 key，不重新生成对象 key。
- DELETED：确认对象缺失后的墓碑；保留数据库记录和 key，不物理删除恢复证据。

“再次核对”不是重新复制。copyStartedAt 占位后进程崩溃，即使 COPY 实际未发出，也不能仅凭一次 HEAD 404 证明此前请求不会稍后提交。继续查询原候选；若需要重新上传，则新建上传行和全新 key，旧行保留人工处理。没有执行器、调度器或自动恢复保证。

对象操作超时先查询实际对象。对缺失结果必须考虑仍在途的写入；不要把不存在当作旧凭证不能再次写入的证明。不按一个宽限期批量删除临时对象、候选或未知旧对象。没有自动孤立对象清理。

## 删除合同变化

以前删除媒体会清空封面并推进文章版本；现在已知封面或正文引用直接阻止删除，用户须先移除引用。整批预检在同一事务中完成，任一引用阻塞则不标记任何项为删除中。

文章/页面保存与已知封面、可解析受管正文图片状态校验使用同一数据库写事务。正文解析包括各语言 img src、配置的受管域名/path、query/fragment 与协议相对 URL。删除还检查明确的链接 logo、用户图片和历史同 key/URL 别名。它不是全量 media_usage：未知历史富文本、外部链接、任意自定义位置和不受控写入仍可能漏掉。

即使没有发现引用，删除也要求明确接受可能破坏未知历史/外部引用的风险。该确认不能覆盖已发现的引用。结果不确定保留 DELETING；确认原始对象不存在后完成。缓存刷新失败返回已提交但公开同步退化，不把已提交删除伪装成失败重做。

## 上线顺序与旧凭证窗口

1. 在只读审计中检查历史媒体字段合法性，报告数量，不回显秘密或直接修复历史数据。
2. 备份并在测试环境演练迁移 0007：按 Drizzle 精确结构在迁移事务内重建 media：先用迁移专用临时辅助表保存全部已知入站 post.cover_id，复制所有历史媒体字段并设 READY/verifiedAt=null，替换表后恢复封面并删除辅助表；未来默认 UPLOADING。实际迁移在 foreign_keys=ON 下验证媒体字段、封面、文章版本和 updatedAt 不变，以及恢复中途失败整次回滚。不要依赖事务内 PRAGMA foreign_keys=OFF。
3. 统一切换服务端和客户端，停止旧 getPresignedUrl/upload 写入口；旧代码不得继续创建未经验证的 READY 行。
4. 记录旧版本最后签发凭证的时间。旧版本曾向最终 key 签发一小时 PUT 和 DELETE；必须等这些凭证失效，并留时钟偏差余量。删除对象或迁移数据库不会撤销这些能力。在该窗口内不要宣称历史最终 key 已不可覆盖或旧写入不会复活对象。
5. 不能直接回退到旧可写代码。回退需禁写或兼容安全补丁；数据库恢复也不能恢复已物理删除对象。

此次实现只在独占临时 file: 数据库执行实际 Drizzle migrator 验证，未运行生产迁移、真实 R2 写删或部署。生产权限、CORS、原生 Sharp 格式支持、请求时限、并发内存/带宽及缓存实际行为仍须在专用测试环境验证。

## R2 与运行环境验证

- 检查服务端凭证可以对指定 bucket 执行 CopyObject、GetObject、HeadObject、DeleteObjects；不给客户端最终 key 写能力。
- 确认 COPY 自动重试关闭；不假设目标 create-only COPY、版本或对象锁存在。
- 核对签名绑定 Content-Type/Content-Length；浏览器自行设置 Content-Length。CORS 只需要精确站点 origin 的 PUT，不再依赖浏览器 DELETE。读取规则按实际 GET/HEAD 需要独立设置。
- 验证 20 MiB 直传、五种格式、动画全帧与拒绝截断/超限；验证两个最大允许解码的峰值内存和请求时长。在确认之前不扩大文件/像素/帧上限。
- 用测试 bucket 演练复制响应丢失、晚到对象、数据库确认丢失、删除后响应丢失和人工核对。不要用生产对象作破坏性测试。
- 准确日志仅记录安全分类与请求标识，不记录签名 URL、凭据、对象内容或原始异常中的敏感参数。
