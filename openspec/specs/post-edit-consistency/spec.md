## Purpose

规定文章主体、翻译与标签关系的原子提交、编辑版本和资源存续期内创建恢复。 这些要求用于约束当前实现及行为回归；规格同步本身不代表持续集成、真实运行环境验证或生产发布已经完成。

## Requirements


### Requirement: 文章表单原子提交

系统 MUST 在同一事务提交主体、翻译与明确指定的四类标签关系，MUST 保留原状态转换、当前服务端能力与资源不变量。省略关系 MUST 不修改，空数组 MUST 清空指定角色；关联写入 MUST 额外验证 post:manage-tags。

#### Scenario: 关联写入失败
- **WHEN** 主体或任一翻译、关联写入失败
- **THEN** 整次事务回滚且不执行成功后的缓存失效，前端保留未保存输入

### Requirement: 编辑版本不允许旁路覆盖

文章更新与删除 MUST 显式携带 expectedVersion；版本检查与写入 MUST 同事务执行，MUST NOT 代填最新版本。影响编辑快照的标签关联删除与显式封面修改 MUST 提升文章版本；浏览计数 MUST 不提升编辑版本。媒体删除按 [媒体生命周期](../media-lifecycle/spec.md) 拒绝已知引用，不再以置空封面绕过引用保护。

#### Scenario: 并发或过期编辑
- **WHEN** 两个客户端基于同一版本保存，或其他操作已改变其关联快照
- **THEN** 旧版本请求被冲突拒绝，不能静默覆盖；前端保留输入并提供明确核对路径

### Requirement: 有限创建去重与安全结果

创建 MUST 以当前主体和稳定 token 唯一识别，并与原始规范化业务输入摘要同事务保存。重放 MUST 重新授权；相同摘要定位现存资源，不同摘要冲突。MUST NOT 声称资源删除后仍永久去重；读写响应 MUST NOT 暴露 token/hash。

#### Scenario: 已提交创建响应丢失
- **WHEN** 同一主体使用原 token 和原输入重试仍存在的创建
- **THEN** 返回原资源的当前安全标识与版本，不重复写入；若已删除或无法确认，恢复流程不自动重新创建

### Requirement: 编辑器只提交完整业务意图

标签选择 MUST 进入表单 dirty 与本地草稿，MUST NOT 独立保存文章关联。编辑基线 MUST 不被脏状态下的 refetch 偷换；成功响应 MUST 只确认提交快照，保留随后编辑。未知创建尝试 MUST 固定原 payload/token 并按账户隔离，MUST NOT 自动重放未知已删除资源。

#### Scenario: 保存期间继续编辑或切换账户
- **WHEN** 请求完成前用户改变输入、记录或账户
- **THEN** 已提交快照与后续修改被区分，旧结果不污染当前表单，创建不因盲目换键而重复执行
