## Purpose

定义公开文章和独立页面在静态缓存、浏览量上报及内容写入后的刷新一致性，确保渲染保持只读、计数失败被隔离，并让成功写入能够及时反映到公开读取结果。

## Requirements

### Requirement: 可缓存内容渲染必须保持只读

文章和页面 Server Component MUST 只执行读取与展示组合，不得在渲染或静态生成过程中增加浏览量或执行其他持久化写入。

#### Scenario: 首次生成公开详情页

- **WHEN** Next.js 首次生成并缓存文章或页面详情
- **THEN** 生成过程不调用浏览量写入，读取失败与计数失败不会互相影响

### Requirement: 浏览量必须通过独立尽力上报路径更新

公开详情页 SHALL 在客户端挂载后通过对应内容 mutation 上报一次浏览量，失败不得阻断正文或向用户显示破坏性错误；成功结果 SHALL 动态更新当前计数，且浏览量写入 MUST NOT 触发公开页面再生成。

#### Scenario: 浏览量接口不可用

- **WHEN** 用户打开正文但浏览量 mutation 失败
- **THEN** 正文保持可读，页面不因计数失败进入错误状态

#### Scenario: 浏览量更新成功

- **WHEN** 已发布内容的浏览量 mutation 返回最新计数
- **THEN** 页面动态显示最新计数且 Full Route Cache 不因该计数写入失效

### Requirement: 内容写入必须失效对应公开缓存

文章、页面和评论的成功写操作 MUST 由对应 Feature server 操作通过一次结构化计划使受影响的公开内容缓存失效，且不得由客户端提供任意缓存路径或缓存 key。其他会改变公开读取结果的分类、友情链接、菜单、设置、标签、用户和媒体写入 server 操作 MUST 失效全部受影响公开缓存。Transport MUST 只调用所属 feature server 操作，不得直接决定失效时机或范围。数据库提交 MUST 作为业务写入成功边界；缓存适配器 MUST 对失败执行一次有限重试，并在仍失败时返回可观测降级结果而不得把已提交写入转换为 API 失败。

#### Scenario: 后台修改友情链接

- **WHEN** 创建、更新或删除会在友情链接页面公开展示的链接
- **THEN** 对应 Link server 操作 MUST 在持久化成功后失效全部公开内容缓存

#### Scenario: 后台更新已发布文章

- **WHEN** 更新操作成功持久化
- **THEN** 对应 server 操作 MUST 失效各语言文章详情缓存，下一次读取可观察到新内容

#### Scenario: 后台更新站点设置或菜单

- **WHEN** 设置或菜单成功持久化
- **THEN** 所有语言的公开布局、列表和 Metadata 在下一次读取时观察到新值

#### Scenario: 后台更新分类、标签或公开作者名称

- **WHEN** 会改变公开列表筛选、标题或署名的数据成功持久化
- **THEN** 受影响的公开列表与详情在下一次读取时观察到新值

#### Scenario: 写入失败

- **WHEN** 持久化写入失败
- **THEN** server 操作 MUST 返回原始失败且不得调用缓存失效端口

#### Scenario: 从其他入口复用写入

- **WHEN** Server Action、后台任务或测试调用与 tRPC 相同的写入 server 操作
- **THEN** 它 MUST 获得与 tRPC 入口相同的缓存失效行为，而无需复制失效调用

#### Scenario: 缓存失效首次失败后恢复

- **WHEN** 数据库写入成功且第一次同步缓存失效失败，但立即重试成功
- **THEN** 缓存适配器 MUST 返回完成结果，server 操作 SHALL 返回原业务成功结果

#### Scenario: 缓存失效持续失败

- **WHEN** 数据库写入成功且两次缓存失效均失败
- **THEN** 缓存适配器 MUST 记录脱敏错误和低基数降级指标，server 操作 MUST 保持原业务成功结果且不得伪造回滚

#### Scenario: 关联快照发生变化

- **WHEN** 分类、标签、用户或媒体删除成功改变文章列表中缓存的关联数据
- **THEN** 对应 server 操作 MUST 在同一次失效计划中请求刷新公开布局并提升文章索引缓存版本

#### Scenario: sitemap 数据发生变化

- **WHEN** 文章、页面、菜单或被菜单引用的分类写入成功改变 sitemap URL、分片数量、可见性或更新时间
- **THEN** 对应 server 操作 MUST 请求立即过期 sitemap 缓存，且下一次成功失效后的读取不得返回旧数据

#### Scenario: 多层缓存按依赖顺序失效

- **WHEN** 同一次计划同时影响文章索引、sitemap 数据缓存和公开路由缓存
- **THEN** 缓存技术适配器 MUST 先提升文章索引版本，再过期 sitemap tag，最后失效详情与布局路由，避免路由在内层旧缓存仍可见时重新生成

#### Scenario: 普通媒体删除后的缓存降级

- **WHEN** 普通媒体记录删除已提交，但公开缓存同步仍失败
- **THEN** Media server 操作 MUST 返回已提交成功及 `publicSync: degraded`，客户端 MUST 保留降级反馈，不得为刷新缓存重做已提交删除；不得创建 DELETED 墓碑或恢复旧生命周期协议

#### Scenario: 空失效计划

- **WHEN** 调用方提交不包含任何详情引用或启用范围的缓存失效计划
- **THEN** 共享缓存计划契约 MUST 拒绝该计划，不得静默报告无操作成功

#### Scenario: 批量删除公开内容

- **WHEN** 一次操作删除多个文章或页面
- **THEN** 对应 server 操作 MUST 在一次失效计划中包含全部详情引用，并且每种共享缓存范围最多执行一次

#### Scenario: 首次提升文章索引缓存版本

- **WHEN** 缓存版本键尚不存在且读取使用隐式默认版本
- **THEN** 第一次失效 MUST 将版本推进到不同于隐式默认值的版本，后续读取不得继续命中旧默认版本缓存

### Requirement: 结构化失效会使 Cache Components 标签过期

除现有 Upstash 版本更新和路径失效外，已有的结构化失效计划 MUST 使对应的 Cache Components 标签过期。该计划 MUST 保留既有失效顺序、重试次数上限和非致命降级结果行为；客户端 MUST NOT 提供任意缓存标签、键或路径。

#### Scenario: 更新文章详情

- **WHEN** 文章 server 操作成功更新指定文章，并提交包含该 ID 的结构化失效计划
- **THEN** 对应文章详情标签和各语言路径失效，下一次正文或 Metadata 读取能获取新内容

#### Scenario: 更新文章索引

- **WHEN** 结构化计划请求刷新文章索引
- **THEN** 基础设施先递增现有 Upstash 版本并立即使 Next.js 文章索引标签过期，再按既有顺序处理 sitemap、详情和布局范围

#### Scenario: 更新共享公开布局数据

- **WHEN** 结构化计划请求刷新布局
- **THEN** 设置、菜单和友情链接的共享公开标签失效，所有语言的布局及依赖这些数据的公开导航在下一次读取时能获取新值
