# 导航数据准备 Specification

## Purpose

定义后台列表写入一致性、规范查询输入和受限单项意图预取，使已确认保存后的列表正确刷新并复用相同查询缓存；保留真实导航重试、账号退出清理和服务器授权，不扩大私有持久缓存边界。

## Requirements

### Requirement: 内容写入成功使后台列表失效

文章与页面创建、更新、删除以及创建结果查询确认成功后 MUST 失效对应adminIndex全部输入变体，保留详情同步与已有会话隔离。刷新失败 MUST NOT 重放已确认成功的写入；写入失败 MUST NOT 伪造成功结果。

#### Scenario: 返回尚未过期的列表

- **WHEN** 用户在列表60秒fresh期间保存内容后返回
- **THEN** 列表重新读取而不将旧标题或缺失新行视为fresh

#### Scenario: 创建响应丢失后确认成功

- **WHEN** 创建结果查询确认该操作已成功
- **THEN** 失效列表且不再次创建内容

#### Scenario: 删除后返回另一筛选列表

- **WHEN** 删除已确认成功且存在其他fresh筛选缓存
- **THEN** 全部列表输入失效，当前视图继续刷新，不在删除失败时伪造成功或重放写入

### Requirement: 首屏查询参数与表格一致

文章与页面列表 MUST 从page1及limit20开始查询，筛选排序变化 MUST 保留既有页码重置契约。预取输入 MUST 与消费输入一致，不生成缺省10条的中间缓存身份。

#### Scenario: 首次挂载列表

- **WHEN** 表格及列表首次挂载
- **THEN** 使用page1/limit20，不先发缺省参数查询

### Requirement: 后台详情仅按明确意图准备

新增与编辑导航 SHALL 使用语义链接并保持样式。详情数据预取 MUST 限于用户hover或focus的单条目标，复用现有查询key、有限staleTime与授权。预取失败 MUST 静默，真实导航消费 MUST 能重新请求；退出清理与硬导航 MUST 保留。

#### Scenario: 悬停后聚焦同一编辑链接

- **WHEN** 用户对同一目标连续表达导航意图
- **THEN** 使用同一查询缓存去重，不自动请求其他行的正文

#### Scenario: 预取失败后点击

- **WHEN** 单条详情预取失败但用户随后导航
- **THEN** 实际详情读取可重试且不因预取失败阻断导航
