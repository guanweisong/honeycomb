## 背景

共享 DeleteBatchSchema 的 100 项上限仍供其他资源使用。分类后台整树选择原先同时截断数组并禁用未选复选框。

## 目标与非目标

移除分类独有的业务数量限制及整段数量文案；保留权限、空数组与 ID 验证、确认对话框、失败保留选择、外键和缓存语义。不改变其他资源限制。

## 决策

分类 schema 复用 IdSchema 定义非空且无 max 的删除输入。前端直接保存完整选择，不拆成多次请求。底层 SQL IN 查询按技术参数预算分段；分类删除和菜单引用查询共用数据库层的 500 参数预算常量，不引入通用批处理框架。菜单查询找到首个引用后只提升一次版本，全部删除分段共用一个事务，提交后仅一次失效缓存。

## 风险与取舍

不承诺无限请求体或无限数据库吞吐；移除的是人为 100 项业务上限。SQL 分段避免单语句参数数量成为较大批次的故障点。任意后续分段失败都回滚此前删除、父子关系和菜单版本。
