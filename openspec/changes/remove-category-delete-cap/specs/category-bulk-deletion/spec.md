## ADDED Requirements

### Requirement: 分类批量删除不设业务数量上限

分类后台和删除接口 MUST 接受超过 100 个有效 ID 的非空选择，MUST NOT 截断选择、禁用超额行或显示已选数量与限制说明。其他资源限制 MUST 保持。

#### Scenario: 全选超过一百个分类

- **WHEN** 用户全选超过 100 个分类并确认删除
- **THEN** 后台 MUST 在一次请求中提交全部所选 ID，不显示数量或上限说明

#### Scenario: 无效输入或权限不足

- **WHEN** 输入为空、ID 不合法或用户无删除权限
- **THEN** 系统 MUST 拒绝请求且不执行删除

### Requirement: 大批量分类删除保持原子性

系统 MUST 对单条 SQL 使用有界参数数量，所有分段删除和菜单版本变更 MUST 在同一事务内执行，成功提交后仅一次缓存失效。未选择后代 MUST 保留，删除父节点后按原有外键置空 parent。

#### Scenario: 后续分段包含菜单引用

- **WHEN** 大批量删除的后续分段含菜单引用目标
- **THEN** 系统 MUST 删除全部所选分类且只提升一次菜单版本

#### Scenario: 后续分段分类被文章引用

- **WHEN** 任意后续分段触发文章外键拒删
- **THEN** 系统 MUST 回滚全部删除及菜单版本，保留原关系且不失效缓存
