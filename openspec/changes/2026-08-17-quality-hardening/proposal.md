# 工程质量持续改进

## 背景

当前工程已有类型检查、Lint、单元测试、覆盖率治理、安全 E2E 和架构边界测试，但部分质量能力仍依赖本地手工执行，文档和测试基线也存在漂移风险。Admin 组件中还存在少量仅有 TODO 的行为测试。

## 目标

- 建立稳定的 CI 质量门禁。
- 让关键工程文档由自动化测试约束，减少脚本、路径和覆盖率数据漂移。
- 补充低成本但有实际行为价值的 Admin 组件测试。
- 补充前台评论表单等高价值交互的行为测试。
- 对 Bundle 分析和生产构建保留可重复的验证入口，并记录环境限制。

## 非目标

- 不改变业务功能、权限模型、数据库结构或生产依赖。
- 不在本 change 中接入真实监控供应商或外部账号。
- 不重写历史 OpenSpec 归档文档。
