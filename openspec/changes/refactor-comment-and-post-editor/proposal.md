## Why

评论客户端、文章编辑页和评论 Router 已同时承担多类职责，导致高频修改需要在大型文件中跨越状态管理、渲染、数据转换和服务端业务编排。需要在不改变任何外部行为的前提下建立清晰模块边界，以降低回归风险和后续维护成本。

## What Changes

- 将评论客户端拆分为身份持久化、提交控制、评论表单和评论树渲染等独立单元。
- 将文章编辑页拆分为表单数据转换、编辑器状态编排、操作按钮和各文章类型字段组件。
- 将评论 Router 中的数据访问、公共 DTO、目标校验和通知编排迁移到职责明确的 service 文件。
- 为抽取的纯函数、Hook 和 service 补充或调整测试，确保重构前后行为一致。
- 保持现有 UI、交互流程、tRPC procedure、输入输出、错误码和路由不变。

## Capabilities

### New Capabilities

- `module-boundaries`: 定义评论前端、文章编辑器和评论 API 的模块职责边界及行为兼容要求。

### Modified Capabilities

无。

## Impact

- 影响博客评论组件、后台文章编辑页面和评论 tRPC 模块。
- 将新增同目录组件、Hook、工具函数和 service 文件。
- 不修改数据库结构、公共 API、页面路由、依赖或产品行为。
