## 背景

文章详情页的推荐查询目前位于单独的 Suspense 边界中，推荐和正文可分别流式输出。用户明确选择移除该边界并同步文档，因此推荐查询改为文章详情服务端渲染流程的一部分。

## 目标 / 非目标

**目标：**
- 删除猜你喜欢的 Suspense 与 Skeleton fallback。
- 在服务端完成推荐查询后再输出文章详情的 RSC 结果。
- 保留推荐查询失败时隐藏模块、文章仍可正常显示的行为。
- 记录文章正文 RSC 预取会等待推荐查询，但最终仍包含正文。
- 固化默认保留预渲染与 URL 预取、避免无必要动态边界和非确定性时间/随机读取的实施规则。

**非目标：**
- 不改变文章正文缓存、URL、Link 预取策略、评论加载边界或推荐查询 API。
- 不把推荐查询迁移到客户端。

## 决策

- 在 `ArchiveContent` 中等待推荐数据，再生成模块 JSX；不让异步推荐组件位于返回树内。使用 Next.js `prefetch()` 把读取推迟到按 URL 的预取阶段，避免 `connection()` 将文章正文一并排除在预取响应之外。
- 将推荐读取保留为服务端公共 tRPC 查询，并保留失败时返回空列表的处理。
- 推荐 tRPC caller 使用只存在于服务端上下文的固定 requestId 并关闭该查询的请求观测，避免按 URL 预取期间生成随机 ID；它不进入文章输出、查询参数或缓存键。
- 关闭观测时 tRPC 中间件必须在计时前返回；启用观测时的耗时和数据库指标时间戳使用单调计时源，避免墙上时钟阻断 Next.js 预取渲染。
- 更新文章详情行为测试，验证推荐 pending 时文章树尚未输出，查询成功或失败后页面才完成。
- 更新生产预取 E2E，要求文章 RSC 预取结果完成后包含正文和“猜你喜欢”模块，并在点击后正确呈现。
- 同步主规格及 `AGENTS.md`：评论和友情链接仍保持独立边界；文章详情推荐查询是经用户确认的例外，会推迟完整文章 RSC 预取响应。
- 固化通用 Next.js 运行时规则：预渲染和 URL 预取为默认行为；仅在确有真实请求时语义或刻意延迟同步 I/O 时使用动态边界；耗时观测使用单调时钟，非确定性时间/随机读取不得仅为观测或内部关联影响预渲染。

备选方案是将推荐查询迁移到客户端组件，以保持正文预取独立；本次按用户选择保留服务端查询并接受响应等待推荐的取舍。

## 风险 / 取舍

- [预取延迟] 推荐查询变慢时，文章 RSC 预取完成也会变慢 → E2E 锁定正文仍包含在完整响应中；推荐查询失败仍降级为空列表。
- [骨架显示] 推荐区不再有独立 Skeleton → 删除不可见且不稳定的局部 fallback，导航时由路由级 loading 状态反馈。

## 迁移计划

不涉及数据迁移或 API 迁移。实现后运行文章详情单测、生产 `content-prefetch` E2E、类型检查、lint 和规格检查。
