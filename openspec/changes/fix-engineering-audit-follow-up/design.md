## 边界

审查结论和已确认范围确定行为。保留现有应用入口、业务所有权及兼容旧数据的路径。实现按认证、业务数据、浏览器和工程门禁四组独立验证。

## 实现方式

- 会话撤销与状态修改使用同一事务。Better Auth 的敏感请求按真实会话关联的用户状态拒绝遗留会话。登录成功、真正认证失败和前置拒绝以 SDK 结果区分。代理头仅在明确可信的入口使用。
- 媒体 guard 接在实际读取边界，仍按数据库结构实时判定。列表和详情维持现有公开投影。邮件继续与提交隔离，只有具备验证依据的收件人才能收到回复通知。批量操作保持原子性和错误优先级。
- 编辑器使用能跨标签页协调或独立保存的持久回执。保留旧凭据和同 token 服务端恢复。评论区域可独立降级，RSC 首屏快照与客户端分页有明确交接，worker 只处理登记的公开资源范围。
- 迁移门禁检查实际使用的 ledger 次序。CI 共用隔离 fixture 准备，保留 lane 的权限、环境与失败语义。Next.js 和同系列配套包固定到已验证的稳定补丁。
- 维护工作按文件真实职责收敛。现有活动 OpenSpec 及历史记录依各自生命周期保存。
