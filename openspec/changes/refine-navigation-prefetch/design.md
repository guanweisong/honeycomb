## 背景

当前Next16.4.2启用cacheComponents与partialPrefetching，auto复用路由壳，true进一步解析URL专属缓存内容；两者不代替客户端tRPC读取。Admin持久QueryClient内60秒fresh列表未被编辑成功失效，首屏{}输入还与表格20条默认值不同。

## 目标与非目标

目标是修正缓存一致性、减少无意义查询身份分裂、按真实交互意图准备必要数据。非目标是全站预取所有正文、添加调度器、修改权限/持久缓存、宣称未测得的速度收益。

## 决策

- 沿用feature-owned成功分支及现有tRPC utils，使对应adminIndex全部输入变体失效；创建确认与直接成功一致，删除保留当前视图刷新并使其他筛选输入失效，不重复刷新当前查询。失败不触发成功路径，刷新失败与写入结果分离，保留账号/编辑会话过期响应隔离。
- 创建结果核对使用 feature 专属小型查询 hook，沿用 tRPC getQueryKey 与所属 client，在 queryFn 成功完成点失效列表；不依赖组件 effect，确保编辑器卸载后成功返回仍能处理。保留 retry:false、账号凭据归属检查，失败或空结果不失效，不增加全局 QueryCache 业务回调。
- 直接统一列表page1/limit20，不新增query key框架，保留表格过滤排序导致的页码重置。
- Blog共享Link只在prefetch未指定时默认true，保留显式false/auto/null；标签及搜索结果auto，文章卡片/菜单/语言切换不统一降级。
- Admin导航使用Link组合保持样式。仅明确hover/focus单条编辑意图时按消费端相同输入预取详情；以现有QueryClient缓存去重，失败静默但不抑制真实点击重试。不改菜单auto、不整表预取正文，不预取写接口。

## 风险与取舍

- 更少Blog URL预取可能使次要链接正文点击后才准备 → 仅密集次要入口采用auto并保留主要内容入口true。
- 提前详情读取可能增加未点击流量 → 只明确意图，复用消费key及有限staleTime，不造长期缓存。
- 保存后的刷新可能失败 → 已成功写入不应显示成写入失败或被重放，列表标记陈旧供后续读取。
- 无生产浏览器网络证据 → 使用真实QueryClient契约测试，最终明确请求数/点击延迟未实测，不绕浏览器权限。

## 迁移与验证

无数据库迁移和新增依赖。源码定向红绿和独立复审收敛后冻结，再执行一轮全量本地门禁；涉及SQLite只使用独占随机合成库并清理。发布/PR/合并另需授权。评论偶发测试和CI附件流程不在本轮。
