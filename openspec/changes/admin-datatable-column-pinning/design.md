## Context

后台通用表格位于 `src/components/DataTable`，列通过 TanStack `ColumnDef` 声明，现有 `ColumnMeta` 已承载筛选选项。表格使用横向滚动容器和浏览器自动列宽；表头、数据单元格、行选择框及行操作单元格分别由共享组件渲染。固定列需要在保留自动布局的同时，保证多个固定列的偏移一致。

## Goals / Non-Goals

**Goals:**

- 让每个列定义可声明固定到左侧或右侧。
- 同侧多列按列顺序堆叠，表头和表体的固定位置一致。
- DataTable 提供 `rowActions` 时，操作列始终固定在右侧。
- 固定列与选择框、行操作单元格并存时不重叠。
- 未启用固定列时保留现有布局和 DataTable props。

**Non-Goals:**

- 增加拖动固定、运行时列宽调整或跨页面保存列偏好。
- 改动管理页数据查询、筛选或排序行为。
- 引入新依赖或更换表格实现。

## Decisions

1. **复用列元数据声明固定方向。** 在 `ColumnMeta` 增加 `pin?: "left" | "right"`，调用方在对应 `ColumnDef.meta` 中配置。相比另传列 ID 列表，这让展示配置与列定义位于同一处，也延续现有 `filterOptions` 的元数据用法。
2. **以实际渲染宽度计算固定偏移。** 当前表格由浏览器自动计算列宽，TanStack 的默认列宽不一定等于单元格实际宽度。共享组件会观测表头列宽，并以该宽度计算左右固定偏移，使列宽随内容或容器变化时重新对齐。未固定时不设置列宽。
3. **选择框和操作列固定于两侧边缘。** 只要存在 `selectableRows`，选择框表头和单元格就固定在最左侧；左固定数据列从选择框之后堆叠。只要存在 `rowActions`，操作列表头和各行操作单元格就固定在最右侧；右固定数据列在操作列之前堆叠。
4. **由表头和表体共享同一偏移计算。** 固定单元格使用不透明背景和明确的层级，表头层级高于表体；左右固定组的边界单元格向相邻滚动区域显示连续渐变阴影，阴影不被行分隔线切断；普通单元格继续自然滚动。
5. **阴影随遮挡状态显示。** 左固定组仅在横向内容已向左移入其下方时显示右阴影；右固定组仅在右侧仍有未滚入视口的内容时显示左阴影。滚动容器到达对应边界或内容无需横向滚动时隐藏阴影。

## Risks / Trade-offs

- [Risk] 测量更新前的首帧中，多个固定列可能暂时重叠 → 首次挂载时立即测量可见表头，并由 `ResizeObserver` 跟踪后续尺寸变化。
- [Risk] 部分测试或非浏览器环境没有 `ResizeObserver` → 实现需进行能力检测，安排一次初始测量并在窗口尺寸变化时重新测量；不得在模块加载时访问浏览器全局对象。
- [Trade-off] 固定列只影响横向滚动位置，不改变其在数据中的逻辑顺序 → 保持现有列定义和排序语义简单稳定。

## Migration Plan

无需数据迁移。现有数据列保持原样；需要固定的数据列只需增加 `meta.pin`。带 `rowActions` 的表格会自动固定操作列。回退时删除该元数据即可；若不需要操作列，可移除 `rowActions`。

## Open Questions

无。固定方向通过 `meta.pin` 配置，左右两侧都支持多列。
