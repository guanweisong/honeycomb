## 背景

基线为 `de5d8887697d1d116661ecefdcf551ec51553169`，隔离工作树和冻结安装已经验证。Node 24.22.1、Bun 1.4.4、OpenSpec 1.4.1；应用版本保持锁文件不变。审查来源及每个条目的实现/保留/待决定分类记录于 `disposition.md`。

## 目标与非目标

目标：让实际消费者、状态所有者和安全边界更清晰，删除无用途扩展点与机械重复。非目标：替换框架、重做 CRUD/编辑器、改变公开 API、减少安全测试、生产迁移、提交或发布。

## 决定

1. **共享库**：请求 ID 只显式传递；Drizzle 关系直接在现有 relations 文件声明；删除未使用的 R2 API。错误规范化由始终执行的 transport middleware 负责，观测位于其外部以看到最终错误；HTTP formatter 继续覆盖 context 构造失败。遥测以一个公共清洗/fail-open 入口包裹内部 sink，保留 SDK 最终隐私过滤与各 sink 独立失败隔离。权限审计元数据如迁移仅归测试，复合权限合同不删除。
2. **组件和路由**：DynamicForm 只支持实际控件和已验证 submit 值；静态 disabled/options 不订阅整个表单。删 Avatar 未消费变体、表格未消费状态、无意义 ref/effect；本地 column metadata 采用类型契约，外部未知筛选值继续运行时验证。路由保留鉴权壳、pending、缓存与并行加载时序，只收窄无消费者的壳/参数。header portal 与 SSR 语言入口不作为机械等价清理。
3. **内容**：sitemap 拥有具体公开 id/updatedAt 与 count 读取；公开 page.index 不改。post detail 去掉重复 ID 预读，保留真实关系读取可见性条件。草稿只共享同步验证的存储机制，保留 post void/page boolean、token 删除、CAS 和未知结果。sidebar 字段使用已有 RHF context；评论边界一次转换 canonical target，保留 SQL 同快照公开条件。
4. **媒体**：用户允许 useInfiniteQuery。采用单一原生 InfiniteData 页缓存而非再建手写缓存；在明确解释全页顺序刷新、重挂载缓存复用和同账户查询共享进度后，用户回复“媒体分页可以批量刷新”。按该原生方向实施，不新增后端批量 API；通过增量规格和明确命名测试记录已批准差异，保留账户隔离、变更后 reset、ID 去重和失败重试。实际 MediaPanel 按账户 key 重挂载；异步 mutation 已有 active/scope guards，哨兵 effect 使用局部 active 标志阻止 disconnect 后排队回调。没有为任意跨生命周期保存的 hook 命令新增通用状态框架。
5. **工具和规范**：CI 使用一个仅管理本次 fixture 的 shell helper；测试进程使用已有 runTestProcess；历史 SQLite 准备只抽普通窄函数。合并精确 ESLint 例外并保留原因。权限/路径历史政策、迁移报告独立可携带性未决定前保留。规范以现有主规格为权威，收敛重复规则时保留独有场景映射；不自动归档历史未验收变更。

## 风险与取舍

- 旧回调、切账户/记录、写后刷新失败 → 保留原竞态矩阵，新增针对改变的行为回归。
- 错误转换和日志泄漏 → 关闭观测、HTTP/context、批请求、未知 SQL 与真实 envelope 测试。
- 抽 fixture 改变清理或历史迁移 → 独占随机 file: SQLite、所有者/符号链接拒绝、真实迁移/回滚，不用远端服务。
- 大范围同时修改 → 明确文件所有权，局部 RED/GREEN 回归，最终一次聚合门禁与独立评审；失败按根因处理，不降低门槛。
