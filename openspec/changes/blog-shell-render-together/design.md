## Context

PR #48 为已发布文章和页面生成了静态参数，但线上刷新仍先显示 Header/Footer，再由正文撑开中间空白。生产构建日志报告 `/[locale]/archives/[id]` 的客户端 URL 参数读取位于 Suspense 外，阻止完整预渲染。当前 Header/Footer 还直接读取设置和菜单，并调用 `connection()`；Footer 在每次请求中读取当前年份。文章详情的整页边界使用 `fallback={null}`，且正文返回前会等待猜你喜欢查询。

即时导航规范要求已发布详情正文及成功的猜你喜欢查询包含在完整 URL 预取结果中，评论等其他请求时数据保持独立。

## Goals / Non-Goals

**Goals:**

- 已发布文章和独立页面直接刷新时，首个预渲染输出包含 Header、正文和 Footer，避免先显示头尾再撑开正文区域。
- 共享布局读取的公开设置和菜单使用可失效的缓存，不引入无语义的请求时边界。
- 路由相关客户端导航组件不阻塞共享页面外壳预渲染。
- 保持正文预取、猜你喜欢完整预取、评论独立加载，以及构建后新增 ID 的运行时解析。

**Non-Goals:**

- 不改变公开 URL、菜单内容、导航高亮规则或评论提交行为。
- 不将猜你喜欢移出完整文章 RSC 预取，也不将其改成客户端请求。
- 不要求构建时枚举所有未来 ID。

## Decisions

1. **缓存共享公开布局数据。** Header 复用 `getCachedMetadataSettings()`，新增缓存的公开菜单读取，使用小时级缓存并挂接现有布局失效标签。设置和菜单写入已有 `refreshLayout` 失效计划，因此更新后仍能刷新缓存。
2. **移除 Header/Footer 上无必要的 `connection()`。** Footer 年份在构建时计算为模块常量；不得为该展示值引入请求时动态渲染。
3. **将 URL hook 边界缩小到客户端叶子组件。** Menu、Breadcrumb、LanguageSwitcher 各自在 Header 内使用局部 Suspense，fallback 保持稳定布局；不包裹整个 Header，也不隐藏已缓存的站点名和菜单数据。
4. **让详情与共享布局同次输出。** 移除文章和页面详情的整页 Suspense。页面参数和公开正文在顶层解析，构建时生成的路径在构建输出中包含完整页面；构建后新增 ID 首次请求等待完整详情响应后写入运行时缓存。猜你喜欢仍在文章详情响应完成前解析；评论和友情链接保持独立 Suspense。
5. **以生产证据验收。** 更新生产浏览器回归检查，断言直接刷新文章和页面详情时第一个 HTML 响应的 main 中包含正文，且正文先于 Footer 输出；同时确认完整链接预取仍包含正文与推荐内容。

## Risks / Trade-offs

- **菜单/设置缓存短时间内可能过期。** → 复用现有 `BLOG_LIST_CACHE_TAG`，并确认设置及菜单写入都触发 `refreshLayout` 失效。
- **未枚举 URL 的导航 hook 可能短暂使用 fallback。** → fallback 保持头部菜单可见，边界只覆盖依赖 URL 的小组件。
- **Footer 年份在跨年后直到下次构建才更新。** → 年份只在构建时计算，符合静态页面契约；部署构建会刷新年份。

## Migration Plan

无需数据迁移。部署后观察构建日志和生产直接刷新；如果回滚，只需恢复共享布局的数据读取和 Suspense 边界，不影响缓存数据格式。
