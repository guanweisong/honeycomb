## 背景

现有媒体状态机用于跨数据库和对象存储失败恢复。用户已明确接受取消状态后异常可能产生孤立文件或失效记录、需手工处理；不能用新的标志、操作表或墓碑暗中保留生命周期。

## 目标与非目标

目标：前后台普通媒体模型、验证后注册、简洁删除、保留权限与已知引用检查。非目标：生产迁移、旧异常记录自动处理、完整跨存储原子性、全站所有引用写入保证、自动重试与自动清理。

## 决策

- prepareUpload 接收现有文件声明加 sha256，返回 intent/uploadUrl/expiresAt。使用 AUTH_SECRET 对版本化、域分离、绑定 actorId、随机媒体 ID、temporary key、文件声明、摘要和有效期的意图签名，不写数据库。
- registerUpload 接收 intent，先验签、核对账户/期限并复查当前权限；存在同 ID 普通记录直接返回，不重写或宣称历史重验证。无记录时先获取验证槽，受限读取临时对象，核对大小/摘要，完整 Sharp 解码。每次尝试产生全新最终键，仅将已验证的内存字节单次 PUT；确认成功才进入短写事务复查权限并主键幂等插入，返回 MediaRecord。
- 不给客户端最终键写入或删除能力。不使用 COPY，不 HEAD 恢复不确定 PUT，不自动重试；数据库提交不确定或并发插入失败时不删除候选，防止误删已引用文件。记录删除后未过期意图可以再次注册，这不是一次性令牌。
- 删除在串行写事务内复查权限、整批已知引用，持有写事务完成对象删除及缺失核对，再物理删行提交。已知引用或未知引用确认不满足时不调用存储。提交后缓存降级仍返回删除成功。
- MediaRecord 为唯一普通读模型；删除生命周期类型、列、筛选、徽章、恢复端点和上传结果状态。保留请求本身的加载/错误和批次成功失败反馈，不将请求反馈保存为媒体状态。
- 文章/页面在原有写事务调用 assertMediaReferencesExist；已存在的未知历史受管 URL 可保持，新未知 URL 拒绝。链接/用户等写入不宣称同等受控。

## 风险与取舍

- 对象写入或数据库提交不确定 → 留下候选孤立文件，人工核对，不清理可能已注册的键。
- 删除部分成功、超时、数据库回滚 → 普通记录可能指向缺失对象；不得宣称跨存储回滚或自动收敛。
- 长写事务持有网络 I/O → 增加锁和超时风险，真实托管环境需要验证。
- 校验 GET 与最终 PUT 最多增加 20 MiB 出站传输 → 保留两槽、20 MiB、40M 像素、100 帧限制和 Node Sharp；真实内存/时限/R2 CORS 仍是发布门禁。

## 迁移计划

新增 0008，不改已应用 0007。迁移先检查非 READY 行数量，任何未解决行中止，不提升、不丢弃。表重建保留普通字段、主键、原 URL/key/时间和封面关系。独占临时 file 数据库测试重放及回滚。生产需额外授权、审计、备份、暂停旧写入、演练、发布新代码；历史最终键上传凭证需等待既有有效期与时钟偏差。回滚需备份恢复和协调旧代码，不能盲目回滚。

## 待验证边界

真实 R2 权限/CORS、宿主事务时限、Sharp 格式支持、资源预算和未知网络失败仅由本地 mock/数据库测试部分覆盖，不等于生产已验证。

## 部署兼容保护

预览和其他环境可能连接同一未迁移数据库。普通查询在旧表上可能静默读取旧状态行，因此不能仅依赖发布顺序说明。媒体服务使用无缓存的实际 PRAGMA 列结构检查，与 Drizzle 普通模型列集完全匹配后才允许操作；不读取状态值、不保留生命周期分支、不执行迁移。媒体列表、上传准备、注册与删除均守卫；受控文章/页面写事务中的引用检查无条件先守卫，检查失败返回 SERVICE_UNAVAILABLE。未知检查结果关闭访问，独立授权迁移完成后下次请求自然恢复。

## 删除事务内的有限网络开销

整批引用检查通过后，使用现有存储适配器一次批量删除去重后的键，不做逐项删除前 HEAD。缺失对象的删除是幂等操作；随后每组最多 8 个 HEAD 并行核对缺失，整组均结束后处理错误。全部核对通过才物理删行。批量删除部分失败或任何缺失核对不确定仍按已接受的弱失败语义回滚数据库，不重放外部操作。该优化减少串行网络往返，不声称已证明真实托管事务寿命足够。
