# 站点快照切片验证

2026-10-20，实施环境本地工作树；没有提交、发布或生产数据库操作。

## 已实现

- menu_revision 单例版本从 0 起；setting.version 从 0 起。0006 SQL、journal、snapshot 对应；设置在同一迁移事务中备份父行和全部翻译、显式清空子行后按精确 schema 重建父表、恢复父行/翻译并删除备份表；全程兼容 foreign_keys=ON。
- menu.saveAll 输入为 { expectedVersion, items }；setting.update 必须 expectedVersion。缺少版本、额外字段、无实际设置字段及非法目标明确拒绝。
- 事务内读取当前启用账户并检查能力，CAS 与数据写入同事务，事务失败回滚全部数据。仅 BEGIN 尚未进入回调的 SQLITE_BUSY 可有限重试，不重试未知提交。
- 编辑用菜单/设置读取在同一事务取版本与数据。页面/分类删除实际影响菜单时，同事务提升菜单版本；失败整体回滚。
- 隐藏/未发布目标仍可存入菜单，公开过滤保持。删除分类留下的孤立菜单可由明确的“移除”操作移除其子树，空树仍不能保存。
- 菜单与设置保存期间、冲突/未知等待核对期间阻止自动接纳后台快照，即使新输入回到了旧基线也不覆盖。已确认保存只更新当次基线，继续编辑仍未保存；切换账户后的旧响应不修改新表单。
- 保存后刷新失败与公开缓存失效失败显示已提交待刷新；未知结果阻止重发，用户读取最新值并明确选择保留本地/放弃本地后继续。

- 23 个相关测试文件、140 个测试通过（menu、setting、category server、后台权限控件与单一事实源架构检查）。

- 使用真正 Drizzle migrate 在独占临时 file SQLite 重放迁移；另从 0005 的旧设置和翻译数据升级，验证版本为 0、身份/翻译保留、菜单单例已创建、PRAGMA foreign_key_check 为空。
- 并发同版本保存恰好一方成功、另一方 CONFLICT；翻译/菜单写入触发器注入失败时原内容和版本保留；页面/分类删除失败时菜单版本不变。

- 临时数据库位于本次 mktemp 独占目录；shell EXIT/HUP/INT/TERM 清理、每个数据库 client close 及测试清理均执行。最后一轮临时根目录删除后再次验证不存在。

## 尚未验证/不承诺

- 全工程测试/覆盖率和构建由主任务统一执行，此记录仅报告本切片实际运行范围。
- 未操作生产数据库、真实账户服务、对象存储或真实浏览器；不把组件测试当作真实浏览器回归。
- 最初的 ALTER ADD 方案通过了数据保留测试，但真实迁移治理发现列顺序与 CHECK 表达式不匹配。已增加该反例并修正 0006，未修改 0000–0005，未放宽治理检查。
- 未验证 CDN、Service Worker、离线旧客户端的陈旧窗口，不提供即时撤回旧公开副本保证。
- 旧客户端不带 expectedVersion 将被拒绝；回退旧写入代码前必须禁写或补兼容，不可绕过版本检查。
- 无永久保存回执；未知结果核对展示当前服务器状态，不能证明某次历史请求执行结果。核对后保留本地是用户明确采用新版本继续编辑，不是自动合并。
