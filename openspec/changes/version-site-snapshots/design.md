## Context
保留现有 menu 行与 setting 单例，避免通用版本平台。

## Goals / Non-Goals
目标：整份编辑快照 CAS、事务身份复核、输入保留、明确失败状态。
非目标：自动合并、永久回执、任意 CRUD 版本、生产迁移。

## Decisions
菜单独立 singleton revision 保证初始空树也有版本；设置父行持有版本。版本和数据须在同一读取事务中返回。保存先条件提升版本，后写整树或翻译，失败一起回滚。删除引用目标时同事务提升菜单版本。现有空目标分类菜单继续可读；重新提交非法目标明确拒绝。
前端只有干净状态可自动接纳后台刷新；保存确认只覆盖当次提交基线，后续输入保持。未知与冲突必须显式核对最新快照，不能自动重发。

## Risks / Trade-offs
无操作回执，响应未知时不能证明历史提交结果。旧客户端缺少 expectedVersion 被明确拒绝。生产迁移、真实并发及缓存行为需要隔离验证和部署前检查，不以 mock 测试替代。

## Migration Plan
在页面 0005 后生成 0006，增加默认 0 版本与菜单单例种子。为保持真实 SQL、snapshot 与 Drizzle schema 的列顺序和 CHECK 精确一致，设置父表使用同一事务内备份/恢复重建；显式保存和恢复全部翻译，不依赖事务内无效的 foreign_keys=OFF。恢复失败必须整体回滚且不遗留辅助表。未执行生产迁移。回退旧代码写入必须禁用，避免绕过版本。
