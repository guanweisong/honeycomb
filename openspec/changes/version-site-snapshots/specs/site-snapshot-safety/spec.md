## ADDED Requirements

### Requirement: 站点快照使用条件版本写入
菜单整树与设置保存 MUST 要求 expectedVersion，并在同一事务中复核当前账户能力、条件更新版本及全部数据。菜单目标 MUST 存在，但未发布页面和禁用分类仍可持久化；公开过滤保持。

#### Scenario: 两个旧快照保存
- **WHEN** 两次保存携带相同版本
- **THEN** 最多一次提交，另一请求返回冲突且不改变任何数据

#### Scenario: 目标删除改变菜单
- **WHEN** 删除页面或分类改变其引用菜单
- **THEN** 同一事务提升菜单版本，使旧整树不能静默恢复删除前快照

#### Scenario: 缺少版本或无权保存
- **WHEN** 请求缺少版本或当前账户已失去能力
- **THEN** 拒绝请求，不代填最新版本，不发生任何保存

### Requirement: 站点表单保留用户编辑
前端 MUST 保留脏输入和保存期间的新输入，并区分冲突、未知结果、确定提交及提交后刷新失败。未知结果 MUST NOT 自动重试。

#### Scenario: 背景刷新与保存期间继续编辑
- **WHEN** 查询刷新或较早保存返回时仍有新输入
- **THEN** 输入保持且仍标记未保存，不被返回快照覆盖

#### Scenario: 保存成功但刷新失败
- **WHEN** 写入已经确认提交而刷新失败
- **THEN** 显示已保存待刷新，不将其报告为保存失败或自动重发

#### Scenario: 切换账户或卸载
- **WHEN** 旧保存返回前编辑器身份改变或卸载
- **THEN** 旧响应不得修改新表单状态
