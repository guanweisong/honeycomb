# 设计

## tRPC 边界

Router 仅负责输入校验、procedure 权限和调用 Service。数据库访问、事务、缓存失效、资源级权限和业务错误保留在业务模块中。原有 procedure 名称和稳定导出保持不变。

## 大文件拆分

权限定义、角色映射、矩阵夹具和授权静态检查按职责分文件；数据库 Schema 按领域拆分时保留稳定入口；测试夹具与行为断言分离。

## 删除策略

通过源码引用、配置引用、动态导入和构建脚本确认无消费者后，才删除依赖或公共包装层。无法证明安全删除的内容保留并记录原因。

## 验证

所有行为重构必须通过相关测试、类型检查和 Lint；最终执行全量测试、生产构建和差异检查。
