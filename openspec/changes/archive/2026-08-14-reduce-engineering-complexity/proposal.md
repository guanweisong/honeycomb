# 降低工程复杂度

## 为什么

当前 tRPC Router、权限矩阵、数据库 Schema 和测试文件承担了过多职责，增加了理解、修改和验证成本。本变更在保持 API 和业务行为兼容的前提下，收敛传输层职责，拆分大型模块，并清理能够确认无调用方的抽象与依赖。

## 范围

- 将复杂 tRPC Router 的数据库写操作、事务、缓存和业务判断下沉到业务 Service/Policy。
- 拆分权限矩阵、数据库 Schema 和大型测试的职责。
- 审计并删除确定无调用方的依赖或包装层。

## 非目标

- 不改变公开 tRPC procedure、输入输出或错误码。
- 不改变权限语义、数据库结构和页面行为。
- 不进行全量技术栈替换。
