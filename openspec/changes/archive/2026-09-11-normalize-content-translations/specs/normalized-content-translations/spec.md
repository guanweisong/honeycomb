## ADDED Requirements

### Requirement: 多语言内容使用实体翻译表持久化

系统 SHALL 将分类、文章、页面、标签和网站设置的多语言字段保存到各自实体翻译表，主表不得继续保存 JSON 多语言列。

#### Scenario: 保存完整双语实体

- **WHEN** 创建具有完整中英文内容的分类、页面或标签
- **THEN** 系统 SHALL 在主表创建一条记录，并在对应翻译表创建 `zh`、`en` 两条受外键保护的翻译记录

#### Scenario: 保存可空文章翻译

- **WHEN** 文章输入只提供某种语言或部分可空翻译字段
- **THEN** 系统 SHALL 只保存真实提供的值，且不得制造另一语言或占位文本

#### Scenario: 删除主实体

- **WHEN** 分类、文章、页面、标签或网站设置主记录被删除
- **THEN** 对应翻译记录 MUST 通过外键级联删除，且不得留下孤儿记录

### Requirement: 对外多语言契约保持兼容

系统 MUST 保持现有 `{ zh, en }` Application、tRPC、表单和读取模型契约，翻译行与 ORM 类型不得泄漏到上层。

#### Scenario: 读取实体详情

- **WHEN** Repository 从主表和翻译表读取实体
- **THEN** Repository SHALL 显式组装与迁移前相同形状和可空语义的多语言对象

#### Scenario: 提交现有表单

- **WHEN** 管理后台继续提交现有 `{ zh, en }` 输入
- **THEN** transport 和 Application SHALL 无需了解翻译表即可调用原有业务操作

### Requirement: 主记录与翻译写入保持原子性

系统 MUST 在一个数据库事务中协调主记录和翻译记录的创建或更新，并保留未提供字段的局部更新语义。

#### Scenario: 创建翻译失败

- **WHEN** 主记录创建成功但任一翻译写入违反约束
- **THEN** 整个创建事务 MUST 回滚，数据库不得保留不完整主记录

#### Scenario: 局部更新网站设置

- **WHEN** 设置更新只提供一个字段的一种语言
- **THEN** 系统 SHALL 只更新该值，并保留其他字段和语言的原值

#### Scenario: 清空可空翻译

- **WHEN** 更新显式将文章或设置的可空翻译值设为 `null`
- **THEN** 系统 SHALL 清空该值，并在该语言行已无任何翻译值时删除空行

### Requirement: 多语言查询保持分页与关系正确

系统 SHALL 在翻译表上执行多语言搜索，并批量加载翻译关系，不得因语言行数量造成实体重复、分页总数失真或 N+1 查询。

#### Scenario: 跨语言搜索

- **WHEN** 搜索词匹配实体任一种受支持语言的目标字段
- **THEN** 系统 SHALL 返回该实体一次，并将其计入总数一次

#### Scenario: 批量读取列表关系

- **WHEN** 列表包含多个实体及分类、标签等多语言关系
- **THEN** Repository SHALL 按实体集合批量加载翻译并组装读取模型，不得逐实体或逐语言查询

### Requirement: 历史多语言数据无损迁移

系统 MUST 通过已提交的版本化迁移把 15 个旧 JSON 列转换为五张翻译表，并在删除旧列前拒绝无效或不满足必填约束的数据。

#### Scenario: 迁移有效历史数据

- **WHEN** 旧 JSON 包含有效的 `zh`、`en` 内容或合法可空值
- **THEN** 迁移 SHALL 原样回填翻译行，保持主记录数量不变，并删除全部旧 JSON 多语言列

#### Scenario: 发现无效必填数据

- **WHEN** 分类、页面或标签包含无效 JSON、缺失语言或空白必填翻译
- **THEN** 迁移 MUST 在修改目标结构前失败并提供只读诊断方式，且不得自动复制、翻译或填充内容

#### Scenario: 验证迁移完整性

- **WHEN** 迁移在隔离的 baseline 数据库副本上完成
- **THEN** 验证 MUST 确认主记录计数、必填翻译、外键关系、旧列移除和 migration ledger 均符合目标结构
