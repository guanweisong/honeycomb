## Context

公开文章与页面采用按需静态生成，但详情渲染同时执行浏览量写入；富文本清理器虽已实现，公开渲染未使用；评论成功后由公开 Server Action 接收任意路径执行缓存失效。CI 的 Turbopack 分析命令默认启动服务，无法作为稳定的批处理门禁。约束是不引入外部服务、保留六位密码和现有 CSP 决策。

## Goals / Non-Goals

**Goals:**

- 所有数据库富文本在进入 React 解析器前清洗，所有 JSON-LD 在进入脚本标签前安全序列化。
- 静态内容渲染保持只读，浏览量通过既有 tRPC 写入口在客户端尽力上报。
- 缓存失效只能由受控的内容标识构造，写操作与对应公开页面刷新形成闭环。
- CI 分析命令能够生成产物并退出；关键门禁不依赖外部服务。
- 文档、依赖和 OpenSpec 严格校验与实际行为一致。

**Non-Goals:**

- 不引入第三方分析、队列、缓存或验证码服务。
- 不移除 CSP `unsafe-inline`，不提升六位密码长度。
- 不把浏览量升级为防欺诈分析系统；仅保证一次页面挂载一次尽力上报。
- 不在本变更中重写全部 E2E 数据基础设施。

## Decisions

1. 新增纯函数安全序列化器，对 JSON-LD 中的 `<` 统一转义；`RichText` 在唯一展示边界调用现有 `sanitizeRichText`。相比要求所有写入口分别清洗，输出边界可以覆盖既有脏数据和未来读取来源。
2. 新增最小 Client Component，在挂载后调用既有文章或页面 `incrementViews` mutation。静态 Server Component 删除写副作用，计数失败被隔离且不影响正文。
3. 删除评论客户端对缓存刷新 Action 的调用；评论 mutation 成功后，由 transport 使用经过 Zod 校验的内容标识调用服务端缓存基础设施。客户端只执行 `router.refresh()`，因此无法提交任意缓存路径。
4. 内容 command 成功后的缓存失效放在 transport 边界调用共享基础设施函数，不把 Next.js API 注入 Domain 或 Repository。
5. Bundle 分析使用 `--output` 批处理模式。CI 只新增当前假配置可稳定执行的测试，不伪造需要真实数据库的全量回归成功。
6. 仅移除 `rg` 与包元数据共同证明未使用的依赖，并用冻结锁文件安装、类型检查和构建验证。

## Risks / Trade-offs

- [客户端上报可被重复调用或拦截] → 保留服务端输入校验与现有 API 限流；本变更不承诺独立访客统计。
- [输出时清洗会改变历史富文本中的危险或不支持标签] → 使用现有允许列表并补充真实渲染回归测试。
- [缓存失效扩大写操作延迟] → 只在成功写入后调用本地 Next.js 缓存 API，不等待外部系统。
- [实验性分析器在受限沙箱仍可能无法启动构建子进程] → CI 使用静态输出参数，验证记录区分代码缺陷与环境权限限制。
