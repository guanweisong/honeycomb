## Context

账号安全页当前通过封装的 `Tabs` 组件维护默认标签，标签切换不会反映到 URL。页面本身为服务端组件，同时依赖服务端读取已启用的社交登录提供方；URL 状态交互需要限定在客户端组件中完成。

## Goals / Non-Goals

**Goals:**

- 使用 `tab` 查询参数标识当前账号安全标签。
- 支持直达链接、刷新恢复，以及浏览器前进后退。
- 保持页面服务端数据读取与现有标签视觉样式不变。

**Non-Goals:**

- 不把标签拆分为独立路由或二级菜单。
- 不修改通用 Tabs 的 API，避免把账号安全页的路由语义泄漏到通用 UI 组件。

## Decisions

- 新建账号安全页专用的客户端标签容器，使用 `useSearchParams` 读取参数、`useRouter` 写入参数。通用 `Tabs` 只负责无状态的视觉与内容编排，保持复用边界清晰。
- 每次切换使用 `router.push` 且 `scroll: false`。这能让前进后退恢复之前查看的标签，同时避免页内跳动；相较 `replace`，用户预期标签切换是可回退的导航。
- 仅接受预定义标签值；参数缺失或非法时展示 Passkey。这样不会让外部 URL 影响页面渲染边界。
- 将读取查询参数的客户端组件置于 `Suspense` 边界中，符合 Next.js 对静态预渲染路由使用 `useSearchParams` 的要求。

## Risks / Trade-offs

- [URL 增加参数] → 仅使用简短且受限的 `tab` 值，默认值不影响既有链接。
- [服务端与客户端边界增加] → 保持服务端页面仅负责提供社交登录数据，客户端容器只负责导航状态。
- [标签切换产生历史记录] → 这是为浏览器前进后退恢复位置的明确取舍。
