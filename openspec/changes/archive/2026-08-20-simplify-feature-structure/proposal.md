# 轻量化业务模块目录结构

## 背景

当前业务模块普遍包含 `admin`、`public`、`transport`、`infrastructure`
等目录。复杂模块需要这些边界，但简单 CRUD 模块中存在大量单文件目录、转发文件和重复样板，增加了定位和维护成本。

## 目标

- 减少业务模块中的样板文件和目录。
- 保留 Post、Comment、User 的领域模型和业务不变量。
- 让简单 CRUD 模块采用更直接的 service、repository、router 结构。
- 不改变现有 URL、tRPC procedure、权限、数据库结构和用户行为。

## 非目标

- 不拆分微服务或改变模块化单体部署方式。
- 不删除真实的跨模块公开契约。
- 不把所有业务逻辑合并进一个全局 service。
- 不以减少目录为目的破坏基础设施隔离或架构边界测试。

## 影响范围

涉及 `src/features` 下的业务模块、相关 import、架构边界测试和架构文档；不涉及数据库迁移和外部 API 契约。
