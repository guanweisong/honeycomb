## 背景

工程已有 strict、分层 DTO 和单元测试。索引空值预检仍报告 94 处错误，枚举和表单还通过普通断言跨越运行时边界。

## 目标与范围

覆盖生产代码、测试和治理脚本的索引安全；修复持久化空结果、领域枚举、查询参数、表单提交和 JSON 数据的类型承诺。保持有效输入及成功响应兼容，不修改数据库或依赖。本次不处理限流、缓存失效算法、通知可靠投递或公开字段裁剪等独立问题。

## 决策

1. 开启全工程 `noUncheckedIndexedAccess`，不通过排除测试或新增断言消除错误。先用命令行参数取得失败基线。
2. Repository 在写入边界确认返回记录；创建没有结果属于基础设施错误，更新未命中属于明确的不存在结果。应用错误经现有 transport 错误映射呈现。
3. 数据库枚举字段在 adapter 校验后进入领域 DTO，不通过修改 schema 的类型声明伪装已验证数据。
4. 前端提交用具体 schema 解析产物；查询和展示使用准确字段或控制流窄化。
5. 外部 JSON 先作为 unknown，再用结构检查或具体 schema 解析。保留 as const 和已验证品牌类型；第三方适配只在最小边界保留具名契约。
6. 相比全局正则禁止 as，使用编译器与有针对性的治理检查，避免误伤导入别名和第三方泛型。
7. 生产源码启用类型感知 ESLint 的五项 no-unsafe 规则，阻止第三方隐式 any 经赋值、返回、调用、属性读取和参数传递进入业务；用实际 lintText 回归测试证明规则生效。测试替身不启用这五项规则，但仍受全工程 strict、索引安全和已有静态治理检查约束。

## 风险与取舍

历史非法枚举会从静默强转变为明确失败，需要错误测试和可诊断信息。合法空值应保持原语义，不填充虚构业务数据。TypeScript 本身和第三方声明无法提供数学意义的绝对可靠性，完成报告应明确保证范围。

## 实施与验证

### 全面复审优化方案

用户在完整审计后要求实施优化。沿用所有者定义、消费者推导的方案，不引入通用 CRUD 或新框架。实现顺序与任务第 5 节对应：

1. Post/Page/Media/Link 的写入 schema 归各 Feature Application；原 schemas 文件仅重新导出，保留名称与校验文案。命令从 schema output 推导，更新仍用 Partial/扩展，其他具有不同输入语义的命令不直接强并。
2. 评论 infrastructure/comment-dto.ts 拥有 toCommentRecord；Post Application 拥有列表与详情结果；AdminUser 从当前用户读取契约派生。
3. identity/auth/providers.ts 拥有提供商 ID、名称与配置筛选，登录页和账号安全共同消费；身份模块的登录历史事件文件拥有事件数组与推导类型，数据库/端口/UI 引用，不反向依赖 ORM。
4. packages/application 的分页契约提供公共四字段和基础默认值；API 默认 updatedAt、仓库默认 createdAt、UI 每页 20 条保留为具名边界策略。领域枚举值用于数据库默认及谓词，不改变数据库 SQL、迁移与合法值。
5. routing 复用领域语言集合但保持原顺序；页面使用已有共享富文本清洗函数。缓存 namespace 注册目录放技术包，缓存校验、指标标签和 Feature 常量都引用它。
6. 先观察所有权结构门禁失败，再实施；运行真实 schema/转换行为测试、完整覆盖率、流程与隔离构建。测试预期保持独立，不从实现计算期望值。

不修改状态流转、公开字段裁剪、缓存版本算法或设置部分语言持久化行为。不修改历史迁移。现有用户工作区改动全部保留，不自动提交。

### 唯一事实源追加设计

用户在复审后明确要求唯一事实源并确认继续实施。收敛已识别的重复定义，不借此修改输入协议、数据库结构、限流或缓存版本算法。

- 多语言完整值、部分展示值和可空输入分别命名，由 Domain 的 schema/工厂定义；tRPC 仅定制中文错误信息，不复制字段规则。
- Media/Tag 在各自 Application 定义读取 schema 并推导 Record；Post 通过这些稳定 Application 边界组合自身读取 schema，并由该 schema 同时提供 Repository 类型与缓存解码。Page 引用相同媒体类型。
- Feature presentation 定义展示别名，contracts 仅重新导出，不再从 Use Case 重新推导第二套名称；公开与后台评论使用不同名称。
- 已有 requireWriteResult 统一缺失写入检查；缓存读写共享 Post 内常量；DataTable 元数据从其 schema 推导；标签两种表单共享字段配置。
- 保留有独立语义的命令、查询、公开和后台边界，不为了减少类型数量让 Domain 依赖 Infrastructure，也不新增万能共享 DTO 模块。
- 用 AST 门禁检查 contracts 只能导出及关键契约不再手写副本；用运行时引用一致性、多语言行为和缓存序列化往返测试验证真正共享。

按持久化契约、前端契约、共享基础设施、索引夹具依次实施，每项运行针对性测试；最终运行类型检查、Lint、全量测试、覆盖率、进程门禁及构建。构建使用隔离的临时副本和假环境变量，避免读取实际服务凭据。
