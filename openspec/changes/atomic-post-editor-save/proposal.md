## 为什么

用户批准按减法后的目标分阶段实施。第一切片解决文章主体与翻译虽已同事务、标签关联却独立保存的问题，并把长时间编辑的版本边界与有限创建去重放在业务写入处。不以全仓搬目录、永久回执或新异步平台作为前置。

## 变更内容

- 扩展既有 post.create/update，一次事务写入主体、翻译与明确提交的四类标签关联；移除只有编辑器消费的 updateTags 独立入口。
- 新增文章 version 和资源关联的创建 token/hash；现有文章 version 回填 0，创建字段允许历史空值。更新与删除显式提交 expectedVersion，不由服务器代填。
- 真实服务端身份与原 capability 映射在写入时验证；提交标签数组额外要求 post:manage-tags。创建结果查询仅限当前主体，响应不泄露内部 token/hash。
- 编辑器本地暂存标签，将标签纳入 dirty 和本地草稿；版本来自实际编辑基线，保存期间后续编辑保留。未知创建使用单一冻结尝试，先查询结果，不自动重建未知已删除资源。
- 保持现有缓存/PWA/publicSync、发布规则、ID/语言和外部服务。不引入永久回执、全量媒体引用、任务调度或新根目录。

## 能力

### 新增能力

- post-edit-consistency：定义文章表单原子提交、版本冲突、有限创建去重与前端结果状态。

### 修改能力

既有内容、安全和缓存规范继续有效。此变更明确改变标签关联即时保存为随文章提交；扩展输入和持久化结构不等于批准生产迁移。

## 影响

涉及文章输入/输出、router/server、编辑器与列表删除、相关 tag/media 关联写入的文章版本保护、前向迁移与测试夹具。仅在独占临时本地数据库验证；不改写已应用迁移，不提交、推送、合并或发布。页面、菜单与设置版本化在首切片验收后逐项推进，不混入当前文章迁移。
