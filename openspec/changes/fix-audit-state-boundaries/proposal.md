## 为什么

全目录审计确认四处状态边界缺陷：文章撤回后的旧详情可驱动再次发布、公开页面媒体携带内部字段、外部搜索留下隐藏批量选择，以及分类/标签提交后翻译读取失败阻断缓存失效。需要以最小范围修复这些可复现行为，而不是再次扩大架构重构。

## 变更内容

- 文章编辑器以已确认提交的状态与版本共同推进操作基线，隔离失败或过期详情刷新。
- 页面公开列表和详情中的媒体在运行时按既有公开读模型白名单投影。
- DataTable 明确外部查询切换和当前页选择的一致性，按稳定业务标识处理刷新后的行；验证 Link、Page 真实消费者。
- 分类和标签在事务内形成可返回的翻译快照，提交后直接执行既有公开缓存失效，避免新增响应协议。
- 为每个缺陷补充针对性失败路径回归，保留现有权限、版本、事务和媒体安全限制。

## 能力

### 新增能力

无。

### 修改能力

- `post-edit-consistency`：明确成功提交后发布状态与版本的同源基线。
- `public-content-safety`：明确公开页面嵌套媒体的运行时字段白名单。
- `admin-module-boundaries`：明确共享表格外部查询、稳定行标识与当前页选择的契约。
- `public-content-freshness`：补充分类和标签翻译结果组装的提交边界场景。

## 影响范围

涉及文章编辑器及头部动作、页面 server 查询、共享 DataTable 及 Link/Page 等选择消费者、分类和标签 server 更新与相应测试。无数据库迁移、依赖变更或新 API 协议；不修改既有 `reduce-safety-duplication` 变更，不包含提交、推送、合并或部署。
