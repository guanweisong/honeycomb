## MODIFIED Requirements

### Requirement: 编辑器只提交完整业务意图

标签选择 MUST 进入表单 dirty 与本地草稿，MUST NOT 独立保存文章关联。编辑基线 MUST 不被脏状态下的 refetch 偷换；成功响应 MUST 只确认提交快照，保留随后编辑。未知创建尝试 MUST 固定原 payload/token 并按账户隔离，MUST NOT 自动重放未知已删除资源。 发布动作 MUST 使用与已确认编辑版本同源的已提交发布状态，不得继续依赖提交前的详情缓存。

#### Scenario: 保存期间继续编辑或切换账户
- **WHEN** 请求完成前用户改变输入、记录或账户
- **THEN** 已提交快照与后续修改被区分，旧结果不污染当前表单，创建不因盲目换键而重复执行

#### Scenario: 撤回提交成功但详情刷新失败
- **WHEN** 已发布文章基于版本 v1 成功撤回为草稿 v2，随后详情读取失败且缓存仍为已发布 v1
- **THEN** 编辑器 MUST 同步推进已提交状态与版本；真实头部动作不得继续以旧已发布状态生成 PUBLISHED/v2 更新，只有明确发布意图才可再次发布

#### Scenario: 提交后旧详情延迟到达
- **WHEN** 已确认的提交快照比随后返回的详情旧缓存更新，或该详情属于其他记录或账户
- **THEN** 旧详情 MUST NOT 覆盖当前已确认状态与版本，保存期间的后续输入仍按既有规则保留
