## MODIFIED Requirements

### Requirement: DataTable 职责独立

系统 SHALL 将 DataTable 的状态参数转换、行选择、表头、表体、工具栏和分页拆分为职责独立模块，同时 MUST 保持现有泛型和交互语义；新增必需的 getRowId 身份解析器时 MUST 同步所有调用者及测试，不允许以数组索引或对象引用回退。外部查询范围改变 MUST 与内部筛选、排序和分页一样安全重置选择；行选择 MUST 基于稳定业务标识而不是对象引用。非选择调用补齐身份解析器后 SHALL 保持原呈现和查询行为。

#### Scenario: 现有列表使用 DataTable

- **WHEN** 既有管理页面在重构后传入既有 columns、data、selection 和 onChange，并补齐稳定的 getRowId
- **THEN** 排序、筛选、分页、选择和操作列行为保持不变

#### Scenario: 测试表格状态

- **WHEN** 单元测试改变排序、筛选或分页
- **THEN** 纯状态 hook 生成与现有 API 相同的请求参数并在必要时重置页码和选择

#### Scenario: 外部搜索更换查询范围
- **WHEN** Link 或 Page 管理列表已经选择记录 A，外部搜索条件切换到不包含 A 的查询或空结果
- **THEN** 表格 MUST 清除旧查询选择并重置到第一页，父级批量操作不得提交 A；数据尚未返回或查询失败时也不得继续使用旧选择

#### Scenario: 同查询刷新替换行对象
- **WHEN** 当前查询刷新产生新对象，但选中行的稳定业务标识仍在当前可选择结果内
- **THEN** 勾选显示、全选判断和父级选择 MUST 按稳定标识保持一致并使用当前行对象，不得因对象引用变化丢失勾选、重复选择或提交过时行数据

#### Scenario: 当前结果移除或禁用选中行
- **WHEN** 同查询的有效结果不再包含原选中标识，或该行变为不可选择
- **THEN** 选择 MUST 移除该行，批量操作目标与当前可选择结果保持一致

#### Scenario: 等待新查询时不能重新选择旧结果
- **WHEN** 查询已切换但列表仍显示旧占位记录且正在读取
- **THEN** 表头和行选择控件 MUST 禁用，选择处理器也 MUST 拒绝改变选择；键盘操作不得重新选择旧目标。同查询刷新不得仅因读取状态而丢弃已有选择。
