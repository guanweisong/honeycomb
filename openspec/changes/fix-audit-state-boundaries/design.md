## 背景

静态审计已定位四个实际调用链，而不是单纯代码风格问题。文章保存后的版本已推进但头部仍读取旧详情状态；页面显式投影没有覆盖嵌套媒体；表格只响应内部参数改变且以对象引用判断选择；分类和标签更新在事务提交后再次查询翻译，查询失败就跳过失效。修复限定在现有 feature 和共享组件内。

## 目标与非目标

目标：以可测试的最小修改闭合四处状态边界，保留真实消费者的操作一致性和服务端安全约束。

非目标：全局架构重写、数据库结构或依赖变更、新增响应协议、重写所有管理反馈、自动发布、修改其他活动 OpenSpec 变更。

## 技术决策

### 文章操作与已确认提交快照同源

为头部动作提供与 baselineVersion 一同推进的已提交状态，而不是直接读取 detail.status，也不直接把用户尚未提交的表单状态视为持久化事实。保存成功即从已提交的规范化快照确认状态；恢复本地草稿所携带的 CAS 来源版本独立保留，不得被已确认发布状态反向覆盖。正常的新详情可更新基线，但旧版本、其他记录或账户的结果不得覆盖它。保留 pending-save 的身份和快照校验，以及保存过程中继续编辑的差异保留机制。

仅禁用刷新失败后的全部操作会损失已成功保存后的可用性；仅刷新查询缓存则仍可能被旧响应覆盖，因此选择显式已确认基线。回归必须走真实头部动作，不能只断言 hook 的表单值。

### 页面嵌套媒体复用公开运行时契约

列表与详情都复用 MediaRecordSchema 解析或等价的单一显式白名单投影；不新增第二套公开字段定义，不以类型断言替代运行时处理。不触碰管理媒体读模型、公开页面可见性、正文引用匹配范围和上传生命周期。

数据库 select 白名单也可限制输出，但现有公共契约更便于保证未来新增内部字段不会泄漏。测试在实际公开调用结果的序列化边界断言精确键集合。

### 表格查询范围和稳定行身份共同约束选择

共享组件通过 getRowId 提供稳定行标识，并让真实外部搜索消费者复用现有表格筛选状态所有者，避免同一查询存在相互脱节的双份状态。Link、Page 等消费者接入统一筛选与业务 ID。外部搜索变化立即清空父级选择并归一到第一页；内部排序、筛选和分页保留既有重置规则。有效数据刷新按 ID 将选择对齐至当前可选择行，剔除消失或禁用行；表体勾选、全选、取消勾选和回调统一使用同一身份规则。

不使用 JSON 序列化整个行对象作为身份，不以每次 data 引用变化一律清空代替一致性处理。避免依赖结果返回后才清空，因为切换查询至请求完成之间同样可能触发破坏性操作。getRowId 为显式必需的身份契约，同步全部生产与测试调用者；非选择调用保持呈现和查询语义。不得退回不稳定索引或对象引用。

### 分类和标签在事务内形成完整返回值

将更新结果翻译读取和完整响应组装纳入原事务，或直接使用事务内已确认数据组装等价结果。提交完成后不再依赖数据库读取，紧接着执行现有 invalidator 并返回相同业务响应及 publicSync。读取组装失败会回滚，因此不需要发明新的“已提交但读取失败”响应协议。

仅把 invalidation 放进 finally 仍会向客户端误报失败；吞掉读取错误并返回不完整翻译会破坏既有响应契约，均不采用。保留分类父子循环约束、必填翻译 upsert 恢复、局部更新语义和缓存适配器既有重试/降级行为。

## 风险与权衡

- 文章基线引入额外状态可能与记录切换不同步 → 针对成功撤回、刷新失败、迟到旧详情及身份切换回归。
- 表格回调或查询身份不稳定可能产生 effect 循环 → 使用稳定身份和比较，仅在有效选择变化时回调；验证所有消费者类型及真实 Link/Page 流程。
- 事务内查询稍微延长持锁时间 → 限于当前实体翻译批量读取，不引入外部请求和事务外副作用。
- 公开媒体解析遇到非法历史记录可能暴露现有数据问题 → 使用当前读模型和既有空值语义，不以泄露原记录作为降级方案。

## 实施与回退

四条独立修复分别先补回归再实施，完成后执行相关测试、类型检查与静态门禁，并按可用环境运行完整测试。无迁移或外部发布步骤；若需回退，仅回退本变更的源代码和测试，不触碰既有安全保护。实际命令、结果和环境阻塞由实施阶段记录，文档就绪不代表实现或验证完成。
