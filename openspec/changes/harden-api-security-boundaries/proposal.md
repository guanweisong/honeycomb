## Why

当前部分公共 API 仍可能返回内部字段、接受客户端绕过资源状态约束，或在缺少资源归属校验时执行写操作。这些缺口会造成密码哈希和评论隐私字段暴露、未发布内容被探测或修改，以及跨资源评论关系污染，需要在继续扩展功能前建立统一的安全边界。

## What Changes

- 用户创建和更新接口改为仅返回显式安全 DTO，禁止密码哈希进入 API 响应。
- 收紧用户列表权限，访客角色不再能够枚举用户邮箱。
- 为标签列表建立公开/后台双入口，公开入口强制只返回启用标签。
- 评论创建接口返回公共 DTO，不包含邮箱、IP 和 User-Agent。
- 评论读取和创建统一校验目标资源已发布且允许评论。
- 评论回复必须与父评论属于同一资源，并要求每条评论仅关联一个目标。
- 文章分类辅助查询以及文章、页面浏览量更新强制限定已发布内容。
- 保留现有评论 CAPTCHA；限流和浏览量去重作为后续独立变更。

## Capabilities

### New Capabilities

- `api-security-boundaries`: 定义公共与后台 API 的资源可见性、响应字段最小化、评论资源归属校验和公开内容写入约束。

### Modified Capabilities

无。

## Impact

- 影响 `user`、`tag`、`comment`、`post` 和 `page` tRPC 模块及其测试。
- 后台标签调用点将由 `tag.index` 切换为 `tag.adminIndex`。
- `GUEST` 调用 `user.index` 将收到权限错误。
- 对未发布或关闭评论的资源执行评论和浏览量操作将被拒绝。
- 不引入新依赖，不修改数据库结构。
