## MODIFIED Requirements

### Requirement: 每个面向用户的 App Router 目标都提供即时且安全的页面外壳

所有可通过客户端导航访问的公开博客和后台路由 MUST 提供静态或缓存的页面外壳，以便导航时立即显示。公开菜单中的分类列表，以及当前已发布文章实际关联的标签和作者列表 URL MUST 在构建时预渲染首屏公开卡片或空状态；空标签、无公开文章的作者及未枚举分类等其他动态列表 URL MUST 在输出列表内容前完成请求时 `params` 与公开列表数据读取，不显示列表专属 Suspense fallback。对于构建时已发布并由详情路由生成的文章和独立页面，直接刷新时的首个预渲染输出 MUST 同时包含共享 Header、对应正文和 Footer；这些内容 MUST NOT 先以只有头尾的空壳显示，再由正文撑开布局。构建时未枚举的文章或页面 ID MUST 仍可在运行时解析；开发态 MAY 在未枚举参数和正文解析期间显示局部 Suspense fallback，生产环境的完整页面及 URL 预取响应 MUST 包含公开正文或 not-found 结果，后续请求可复用缓存。其他请求时 API、依赖路由的未缓存读取和授权检查 MUST 放在路由局部的 Suspense 边界后；文章详情页的猜你喜欢查询遵循下一 Requirement 所述例外。应用 MUST NOT 使用 `instant = false` 规避即时导航或预渲染验证。fallback MUST NOT 暴露后台私有内容或绕过授权。

#### Scenario: 刷新构建时已生成的公开详情

- **WHEN** 访客直接刷新构建时已生成的文章或独立页面 URL
- **THEN** 首个预渲染输出同时包含 Header、详情正文和 Footer，不先显示缺少正文的共享页面外壳

#### Scenario: 首次访问构建时未列出的公开详情 ID

- **WHEN** 访客直接刷新或导航访问构建时未生成的文章或页面 ID
- **THEN** 开发态路由可以通过局部 Suspense 解析 URL 参数；生产环境完整页面及 URL 预取响应包含详情正文或 not-found，后续请求复用缓存

#### Scenario: 刷新构建时生成的分类列表

- **WHEN** 访客直接刷新构建时从公开菜单生成的分类列表 URL
- **THEN** 首个预渲染 HTML 已包含该 URL 对应的首屏文章卡片或空状态，不先输出列表骨架

#### Scenario: 同步刷新未生成的动态文章列表

- **WHEN** 访客直接刷新分类、标签或作者列表 URL
- **THEN** 路由等待该 URL 的参数和公开列表数据完成后输出卡片或空状态，不输出列表专属 Suspense 骨架；完整 URL 预取仍包含首屏卡片

#### Scenario: 刷新动态文章列表

- **WHEN** 访客直接刷新分类、标签或作者列表 URL
- **THEN** 页面在解析该 URL 参数并完成公开列表读取后一次性输出对应卡片或空状态，不先输出列表 Suspense fallback

#### Scenario: 后台页面的请求级检查尚未完成

- **WHEN** 后台目标页面在导航期间需要执行会话或能力检查
- **THEN** 检查访问权限期间显示不含敏感信息的 fallback，只有授权成功后才渲染受保护页面内容

#### Scenario: 当前用户没有访问后台目标页面的能力

- **WHEN** 请求级路由检查发现已认证用户无权访问后台目标页面
- **THEN** 使用现有的禁止访问重定向或页面，目标页面的受保护内容不得出现在页面外壳或 fallback 中

### Requirement: 动态语言和内容参数无需完整构建时枚举

根 `[locale]` 和列表 slug MUST NOT 依赖 `generateStaticParams()` 枚举完整参数。列表路由 MAY 用 `generateStaticParams()` 为构建时公开菜单中的分类，以及已发布文章实际关联的标签和作者生成全部支持语言的 URL，并 MUST 在预渲染 HTML 中包含对应列表首屏卡片或空状态；空标签、无公开文章的作者及未枚举分类/标签/作者仍 MUST 可在运行时解析，页面须等对应公开列表数据完成后返回且不得显示列表专属 Suspense fallback。博客站内链接的完整 URL 预取响应 MUST 包含对应列表首屏卡片。文章归档 ID 与独立页面 ID MAY 使用 `generateStaticParams()` 预生成构建时已发布内容的路径；该枚举 MUST 使用已发布内容的轻量 ID 投影，并生成全部支持语言的路径。文章和页面详情路由 MUST NOT 将完整 ID 枚举作为路由正确性的前提；构建后新增或未枚举的 ID MUST 仍可在运行时解析。空内容时，详情生成器 MUST 按 Cache Components 非空参数要求返回不会暴露内容的无效占位 ID，并由既有 ID 校验处理为 not-found。文章和独立页面详情路由 MAY 在开发态对未枚举参数保留局部 Suspense 边界。详情路由在构建时已生成的公开 ID MUST 在预渲染输出中包含正文；未枚举 ID MUST 可在运行时解析，生产环境完整页面及 URL 预取响应 MUST 包含正文或 not-found。

#### Scenario: 构建当前已发布详情路径

- **WHEN** Next.js 构建应用且数据库包含已发布文章或独立页面
- **THEN** 每个已发布 ID 都为全部支持语言生成详情路径，并使用原有公开详情读取生成页面内容

#### Scenario: 构建当前公开菜单中的分类列表

- **WHEN** Next.js 构建应用且公开菜单包含分类
- **THEN** 每个有效分类路径都为全部支持语言生成预渲染 HTML，且 HTML 包含该分类首屏公开卡片或空状态

#### Scenario: 构建当前已发布内容的标签和作者列表

- **WHEN** Next.js 构建应用且已发布文章关联标签或作者
- **THEN** 每个相关 ID 都为全部支持语言生成列表路径，路径由轻量 ID 投影确定，HTML 包含对应首屏公开卡片或空状态

#### Scenario: 访问空或未枚举的列表参数

- **WHEN** 访客访问空标签、无公开文章的作者，或构建后新增的分类/标签/作者列表 URL
- **THEN** 路由仍在运行时解析 URL，等待对应公开列表数据后返回卡片或空状态

#### Scenario: 构建后访问新增详情 ID

- **WHEN** 访客访问未在构建参数中列出的文章或页面 ID
- **THEN** 路由仍在运行时解析该 ID，完整页面响应呈现公开内容或 not-found；URL 预取完成后包含正文，后续访问复用缓存

#### Scenario: 构建时没有已发布详情

- **WHEN** Next.js 构建应用且没有已发布文章或独立页面
- **THEN** 生成器提供无效占位 ID 以满足非空参数要求，详情路由由既有 ID 校验返回 not-found
