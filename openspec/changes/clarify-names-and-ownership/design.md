## 背景

以 52af7a7 的已验证实现为基线，落实 28 项命名与归属建议。结构不重新分层；改动由实际消费者证明。

## 目标与非目标

目标是名称表达职责、测试具有真实所有者、规范唯一。非目标是产品变化、数据库迁移、依赖升级、公开 API 变化和部署。

## 决策

1. 内部重命名同步 import、动态 import、mock、路径门禁、覆盖率配置和当前文档；没有外部消费者的旧入口直接删除，不建兼容 barrel。
2. 评论请求 Promise 和 Suspense 保留在实际边界；管理导航归 app/admin；R2 和公开失效器表达真实技术职责。
3. 单模块测试就近，跨模块行为进入 integration，结构断言进入 architecture，执行配置进入 tooling。移动不改变运行环境、断言、权限证明或进程分组。
4. 后台四组规范只由 admin-module-boundaries 维护，保留其更完整场景及 E2E 库存规则。媒体只改 Requirement 标题，保留 capability 和迁移编号；当前增量同步名字，旧生命周期提案追加已被取代说明。
5. 既有行为测试先调整消费者并确认失败，再实施最小重命名并验证。文档变更以严格规格、引用和原场景保留检查验证。

## 风险与取舍

- 字符串路径遗漏：检查 mock、AST 源文件、内联打包、覆盖率和 CLI 配置，并运行全量 CI。
- 测试移动影响库存：记录改名前后文件与场景数量，保持完整 Chromium 项目发现。
- 历史路径失真：历史报告保留正文，只追加当前导航；不重写旧通过结论。
- 本地缺少 Sentry 安装：局部测试与结构检查不代表完整类型/Lint 通过，最终以精确提交 CI 为准。
- 已知评论键盘取消场景曾重试通过且未归因：保留断言和超时，后续失败保留证据，不因整理掩盖。

## 迁移与回退

同一提交包含源码、消费者和规则的完整迁移；不涉及持久数据。回退整次重构提交即可，不能只回退路径或消费者的一侧。
