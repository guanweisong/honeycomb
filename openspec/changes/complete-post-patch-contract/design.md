## Contract

保留现有按字段携带 {en, zh} 的稀疏文章输入。更新新增可选 removeLocales（en/zh，不重复）；提供任意同 locale 字段（包含 null）与删除冲突。整个本地化字段为 null 表示清空两种语言，因而不能同时删除任一语言。省略字段和语言保持原值；空字符串不删除翻译。清空所有值保留既有行，但不凭空创建没有值的语言行；create 继续只创建有值的稀疏翻译。

创建和更新采用 post 专有严格 schema，避免改变其他功能的共享本地化 schema。命令重新 parse，失败返回安全 BAD_REQUEST，不输出原始输入或验证细节。更新语言删除和主体、关联写入处于同一版本事务，失败全回滚。关系能力仍由写时真实身份检查。

## Verification

先证明新 schema 和真实本地隔离数据库行为失败，再实现并复验。覆盖删除、冲突、全空行保留、空字符串、未提交语言、未知字段、直接调用、版本一次递增和关系失败回滚。既有双语页面和设置合同不变。父任务负责全仓最终质量验收。

## Integrated follow-through

严格命令 schema 要求编辑器先明确投影业务 DTO，不再依赖 schema 静默删除表单 id 和标签选项对象；本地草稿与选项仍保留原模型。媒体引用检查复用媒体领域 helper，在同一文章事务使用有效封面、合并/清理后的正文和先前正文；不能只验证本次原始输入。

随机推荐先选择 ID 再读取翻译会在两次查询之间撤回时混合公开资格和新私密值。真实本地数据库测试在首次查询之后撤回并更新标题，证明旧实现泄漏；改为一个限定 10 条已发布主体的子查询并 join 白名单翻译列。单次结果可以是撤回前合法公开快照，下一次读取排除已撤回主体，不宣称数据库响应能撤回已发出的旧公开数据。
