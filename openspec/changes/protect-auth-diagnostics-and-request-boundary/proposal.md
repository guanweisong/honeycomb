## 为什么

已观察到 Better Auth 默认日志打印包含会话查询绑定的原始数据库错误，以及后台请求相关的预渲染取消诊断。用户已批准认证日志脱敏与验证、修复认证读取的预渲染边界；没有证据证明会话被滥用或这些诊断对应用户可见 500。

## 变更内容

- 为 Better Auth 配置专用安全日志入口，仅输出固定操作和明确白名单诊断分类，不序列化原始消息、SQL、参数、凭据、堆栈或 cause。
- 用已安装 Next.js 的实际请求/运行时预渲染行为验证后台认证入口；只在证明需要的 app 请求所有者等待实际请求，不在全局数据库或通用认证库添加框架屏障。
- 保留认证及数据库抛错、用户状态、会话、权限与日志级别合同；日志故障不能改变认证结果。

## 能力

### 新增能力

- 无。

### 修改能力

- `runtime-error-capture`：增加认证 SDK 白名单诊断与后台请求所有者的预渲染边界验收。

## 影响

涉及 `src/auth.ts`、专用认证日志适配器、被验证的后台认证 app 入口及定向测试。不改 Upstash 配置、凭据、权限、撤销、Sentry 配置、数据库结构或依赖；提交和发布仍由协调者执行。
